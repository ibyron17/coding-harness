## 요구사항 요약

`.claude/dashboard.html` 은 **프로젝트당 1파일**인데 쓰기 주체(메인 세션)는 **N개**가 될 수 있다.
같은 프로젝트에서 두 메인 세션 A·B 가 동시에 전체 경로 작업을 하면 세 가지가 일어난다.

**① init 클로버링.** `/dashboard init` 은 무조건 `rm -f` + 템플릿 Write 다
([`commands/dashboard.md:370-376`](../../commands/dashboard.md)). B 의 `init` 이 A 의 진행 상태와 작업
추적 로그를 통째로, 조용히 지운다.

**② 조용한 상태 오염 — 이것이 핵심 문제다.** A 는 자기 대시보드가 대체된 것을 **모른다.**
`step`·`log`·`impl` 절차는 매 호출마다 grep 으로 앵커를 **새로 찾기** 때문에, A 의 다음 호출은
실패하지 않고 **B 의 대시보드를 성공적으로 수정한다** — B 의 3단계를 A 가 `done` 으로 뒤집는 식이다.
실패라면 감지되는데, 성공해 버리기 때문에 감지되지 않는다.

**③ 허브 표시.** `/hub` 의 티어 1 표시와 카드 모달은 **마지막으로 `init` 한 세션의 것만** 보인다.
이번 변경에서는 **바꾸지 않는다**(R4 의 YAGNI 기록 참조).

이 PRP 는 ①을 **확인 가능한 사건**으로, ②를 **감지된 중단**으로 바꾼다. ①을 완전히 막지는 않는다 —
막으려면 파일을 세션별로 쪼개야 하고 그것이 안 1이다(R4).

### 사용자 스토리

> 같은 프로젝트에서 두 번째 세션을 열어 다른 작업을 시작할 때, 첫 세션의 대시보드를 모르고
> 날려 버리는 일이 없었으면 좋겠다. 이미 날아간 뒤라면, 내 `step` 호출이 남의 대시보드를
> 조용히 고치는 대신 "이건 네 대시보드가 아니다"라고 말해 줬으면 좋겠다.

## 확정된 전제 (재론하지 않는다)

1. **`.claude/dashboard.html` 은 기능 단위로 만들고 끝나면 지우는 임시 산출물이다**
   (`.gitignore` 대상, 확인함). 마이그레이션 장치를 만들지 않는다 — 구세대 파일은 "고지 후 그대로 동작"이
   기존 관례다.
2. **서브에이전트는 이 파일에 접근하지 않는다**(`session-dashboard.md` 설계 결정 4). 소유권 개념의
   주체는 **메인 세션**뿐이다. 토큰을 서브에이전트에게 전달하지 않는다.
3. **DOM 자체가 상태다.** 별도 상태 파일(JSON·락 파일)을 만들지 않는다.
4. **절차는 결정적이어야 한다** — 폐쇄 어휘, Bash 호출 최소화, 판단이 개입할 여지 제거.
5. **허브는 `/dashboard` 의 DOM 을 읽기만 한다**(`hub-dashboard.md` 쟁점 1). 이번 변경은 허브가
   **읽지 않는 지점**만 건드린다.
6. **실패 비차단 원칙**(「자동 발행」). 소유권 장치의 실패가 대시보드 기능 자체를 죽여서는 안 된다.

### 허브 무변경 검증 (요구 6 — 직접 읽고 확인한 결과)

`hub/bin/hub_parse.py` 전문을 읽었다. 정규식은 7개이고, **`#dz-log` 를 매칭하는 것은 하나도 없다.**

```python
_TITLE_PATTERN    = re.compile(r'<h1 id="dz-title">(?P<text>.*?)</h1>')
_SUBTITLE_PATTERN = re.compile(r'<div class="sub" id="dz-subtitle">(?P<text>.*?)</div>')
_PROGRESS_PATTERN = re.compile(r'<div class="pct" id="dz-progress-pct">…')
_UPDATED_PATTERN  = re.compile(r'id="dz-updated">(?P<text>.*?)</div>')
_STEP_LINE_PATTERN / _IMPL_LINE_PATTERN / _CELL_LINE_PATTERN   # li·td 줄
```

모듈 docstring 도 명시한다: *"로그 항목(#dz-log 의 `<li>`)은 여러 줄에 걸쳐 있어 파싱하지 않는다."*
`grep -rn 'dz-log\|data-server-port\|dz-updated' hub/bin/*.py hub/bin/hub_template.html` 의 결과는
**docstring 1건 + `_UPDATED_PATTERN` 1건**뿐이었다(코드에서 `dz-log` 를 읽는 곳 0건).

**결론: `#dz-log` 여는 태그에 속성을 추가해도 허브 티어 1은 영향을 받지 않는다.** 이 검증은
T25-75(역방향)로 고정한다.

> **반대로, 이 검증이 왜 위치 선정의 결정적 근거인가**: 위 네 정규식은 `id="dz-title">` 처럼
> **닫는 꺾쇠까지 포함한 완전 일치**다. `#dz-title`·`#dz-updated`·`#dz-progress-pct` 중 어디에든
> 토큰 속성을 끼워 넣는 순간 `parse_dashboard_html` 이 `None` 을 돌려 **허브 티어 1 전체가 조용히
> 사라진다.** `#dz-log` 는 허브가 유일하게 **읽지 않는** 동적 셀렉터다(결정 O2).

## 결정

### 결정 O1 — 토큰 형식은 **소문자 hex 8자리**, 생성은 `init` 1단계 Bash 에 얹는다

```bash
mkdir -p .claude && rm -f .claude/dashboard.html && od -An -N4 -tx1 /dev/urandom | tr -d ' \n' && echo
```

- 출력은 `[0-9a-f]{8}` 8글자 정확히 하나다(이 환경에서 실행 검증: `3ccc4284`, `fe4b851c`, `4868ef39`).
- **Bash 호출이 늘지 않는다.** `init` 1단계는 이미 `mkdir`+`rm` 을 한 번 부른다. 파이프는 `&&` 보다
  결합이 강해 `A && B && (C | D) && echo` 로 파싱된다(검증함).
- 32비트(약 43억분의 1) 충돌 확률이면 충분하다. 이 값은 **같은 프로젝트에서 동시에 살아 있는
  대시보드 2~3개**를 구분하는 것이 전부다.

| 대안 | 판정 |
|------|------|
| **`od -An -N4 -tx1 /dev/urandom`(채택)** | `od`·`tr` 은 POSIX 유틸리티. macOS·Linux 공통. 기존 Bash 에 얹혀 호출 0 증가 |
| `openssl rand -hex 4` | **거부.** 있을 가능성이 높지만 보장되지 않는다. 없는 환경에서 폴백 분기가 생긴다 |
| `python3 -c "import secrets…"` | **거부.** 「자동 발행」이 `python3` 없음을 **정상 경로**로 다루는데, 토큰 생성이 `python3` 을 요구하면 그 환경에서 R1·R3 가 통째로 죽는다 |
| 타임스탬프(`date +%s`) | **거부.** 같은 초에 두 세션이 `init` 하면 충돌하고, 무엇보다 **예측 가능**해 "우연히 같은 값"이 재현 가능한 형태로 존재한다 |
| PID·세션 ID | **거부.** 메인 세션이 자기 세션 ID 를 아는 표준 수단이 없다(R4 의 근거이기도 하다). `$$` 는 Bash 도구 호출마다 달라진다 |

> 2026-09-02 실측으로 세션 ID 가 `CLAUDE_CODE_SESSION_ID` 로 관측됨 —
> hub-session-tree-and-per-session-dashboards.md ST1.

### 결정 O2 — 토큰은 `#dz-log` 여는 태그의 `data-owner-token` 속성에 둔다

```html
<ul class="log" id="dz-log" data-owner-token="4868ef39" data-server-port=""></ul>
```

**근거 넷.**

1. **허브가 읽지 않는 유일한 동적 셀렉터다.** 위 「허브 무변경 검증」 참조 — 다른 후보는
   전부 허브 정규식을 깬다.
2. **`log` 가 이미 매 호출마다 grep 하는 줄이다**(0-a). `log` 의 검증 비용은 **정확히 0**이다.
   `step`·`impl` 도 기존 grep 에 `-e 'id="dz-log"'` **패턴 하나**만 더하면 되므로 **Bash 호출은
   한 번도 늘지 않는다**(결과 줄이 1줄 늘 뿐이다).
3. **불변식 8의 보호를 그대로 받는다.** 폴링 동기화는 `#dz-log` 에 `innerHTML` 만 대입하므로
   **여는 태그의 속성을 건드리지 않는다.** `data-server-port` 가 이미 이 성질에 기대고 있고
   (폴링 동기화 계약 표에 명문화돼 있다), 토큰도 같은 자리에 있어 같은 보호를 받는다.
4. **선례가 있다.** `data-server-port` 가 "새 셀렉터 행이 아니라 `#dz-log` 행의 하위 개념"으로
   문서화된 방식을 글자 그대로 재사용한다 — 새 개념을 만들지 않는다.

**불변식 정합성 확인** (세 가지 모두 성립):

| 불변식 | 판정 |
|--------|------|
| grep 유일성 (`id="dz-log"` 는 문서 내 유일) | **유지.** 속성이 늘어도 `id="dz-log"` 문자열은 여전히 그 줄 하나뿐이다. `<style>`·헤더 주석의 `#dz-log` 는 `id=` 형태가 아니다 |
| 1줄 1요소 (불변식 2·5) | **무관.** `<ul>` 여는 태그는 원래 한 줄이며 자식 `<li>` 를 건드리지 않는다 |
| 스크립트가 읽지도 쓰지도 않음 (불변식 8) | **동일하게 적용.** 불변식 9로 명문화한다. 스크립트가 `id="dz-log"` 문자열을 만들면 안 된다는 grep 유일성 불변식도 그대로다 |

| 대안 위치 | 판정 |
|----------|------|
| **`#dz-log[data-owner-token]`(채택)** | 위 4가지 근거 |
| `<html data-owner-token>` · `<meta>` in `<head>` | **거부.** 허브를 깨지는 않지만, 세 절차가 **새 grep 패턴 대상**을 하나 더 갖게 되고 폴링·PiP 가 문서 루트를 다루는 방식(스타일 복사, `.wrap` 이동)과의 관계를 새로 검토해야 한다. 얻는 것이 없다 |
| `#dz-updated` · `#dz-title` · `#dz-progress-pct` | **거부.** `hub_parse` 정규식이 완전 일치라 **티어 1이 통째로 사라진다**(GOTCHA 4) |
| `#dz-log-card` (카드 `<div>`) | **거부.** 불변식 4가 "스크립트가 이 id 를 참조하지 않는다"만 보장할 뿐 절차가 이 줄을 grep 하지 않는다 → `step`·`impl` 이 패턴을 하나 더 얹는 것은 같지만, `log` 의 **비용 0** 성질을 잃는다 |
| HTML 주석(`<!-- owner: … -->`) | **거부.** DOM 계약이 아니라 자유 텍스트가 된다. 표에 올릴 수도, 폴링 계약으로 보호할 수도 없다 |

### 결정 O3 — "최근 갱신" 판정은 **파일 mtime**, 임계값 **30분**, 폐쇄 어휘 3개

```bash
if [ ! -f .claude/dashboard.html ]; then echo ABSENT; else
  if [ -n "$(find .claude/dashboard.html -mmin -30)" ]; then echo RECENT; else echo STALE; fi
  grep -o -e 'data-owner-token="[^"]*"' -e 'id="dz-title">[^<]*' .claude/dashboard.html || true
fi
```

출력 첫 줄은 `ABSENT`·`RECENT`·`STALE` 중 하나다(이 환경에서 세 경로 모두 실행 검증함).
2번째 줄부터는 **보고용 참고 정보**이며 판정에 쓰지 않는다.

| 대안 | 판정 |
|------|------|
| **파일 mtime(`find -mmin -30`)(채택)** | Bash 1회, 파싱 없음, 타임존·로케일 무관. `.claude/dashboard.html` 을 쓰는 주체가 오케스트레이터뿐이라 **mtime 이 곧 "마지막 대시보드 활동"** 이다 |
| `#dz-updated` 텍스트 파싱 | **거부.** ① `2026-08-12 17:02` 를 파싱해 현재 시각과 빼는 산술이 LLM 판단에 들어온다(결정성 저하) ② 초 단위가 없어 분해능이 낮다 ③ 무엇보다 **같은 정보의 출처가 둘이 된다** — 이 저장소가 두 번(불변식 7·8) 명문화한 실패 유형이다 |
| `lsof`·프로세스 탐색으로 "살아 있는 세션" 확인 | **거부.** 대시보드를 쓰는 것은 프로세스가 아니라 대화 세션이다. 열려 있는 파일 핸들이 존재하지 않는다 |

**임계값 30분 = 허브 `stale_after_minutes` 기본값**(`hub_model.py:69`, `hub/README.md:312` 확인)과
같은 값을 쓴다. 두 도구가 "이 프로젝트는 지금 활동 중인가"를 서로 다른 숫자로 판정하면 화면과
프롬프트가 어긋난다. 상수 이름은 절차 문서에 `30분(허브 stale_after_minutes 와 같은 값)` 으로 명기한다.

**임계값이 놓치는 구간을 R3 가 받는다.** 세션 A 가 구현 단계에서 40분간 대시보드를 갱신하지
않으면 B 는 `STALE` 로 보고 조용히 덮어쓴다. 이때 **A 의 다음 `step` 호출이 `FOREIGN` 으로 중단된다** —
R2 는 빈도를 줄이고, **R3 가 감지를 보장한다.** 둘은 서로의 대체재가 아니다.

### 결정 O4 — 확인 여부는 **mtime × 토큰**으로 정한다 (묻는 횟수를 최소화)

| 첫 줄 | 파일의 토큰 | 행동 |
|------|-----------|------|
| `ABSENT` | — | 조용히 생성 (오늘과 동일) |
| `STALE` | 무엇이든 | 조용히 재생성 (오늘과 동일) |
| `RECENT` | **이번 세션이 각인한 토큰과 같다** | **조용히 재생성** — 같은 세션의 다음 작업이다 |
| `RECENT` | 다르다 · 없다 · 이번 세션에 토큰이 없다 | **확인 절차** |

세 번째 행이 이 결정의 핵심이다. mtime 만으로 판정하면 **가장 흔한 정상 흐름**(한 세션이 기능 A 를
끝내고 곧바로 기능 B 를 시작하며 `init` 재호출)이 매번 확인 프롬프트를 띄운다. 토큰 비교 한 번으로
그 마찰이 사라진다 — 사용자가 지적한 "덮어쓰기 확인이 반복적으로 걸리적거리는" 상황(R4 재방문
트리거)을 **설계 단계에서 미리 제거**한다.

### 결정 O5 — 확인은 `AskUserQuestion` 선택지 2개. **묻기 전에 아무것도 지우지 않는다**

- 질문: **"`.claude/dashboard.html` 이 30분 이내에 갱신됐습니다 — 다른 메인 세션이 사용 중일 수
  있습니다(현재 제목: 「{제목}」). 어떻게 할까요?"**
- 선택지 A — **덮어쓰기**: "기존 대시보드를 지우고 이번 작업으로 새로 발행합니다. 그 세션의 진행
  상태와 작업 추적 로그는 남지 않습니다."
- 선택지 B — **대시보드 없이 진행**: "이번 작업에서는 대시보드를 만들지 않습니다. 기존 파일을 그대로
  두고, 이후 `step`·`log`·`impl` 호출도 생략합니다. 앞으로 계속 끄려면 `/dashboard off` 를 쓰세요."

- **`AskUserQuestion` 이 없으면** 같은 내용을 평문으로 묻고 답을 기다린다(`/dashboard on|off` 의
  `README.md:32` 관례와 같은 형태다 — 도구 유무로 문구가 갈리지 않는다).
- **선택지는 정확히 2개다.** "다른 이름으로 저장" 같은 제3의 길은 안 1의 파일 분리를 부분 도입하는
  것이라 이번 범위 밖이다(YAGNI). `AskUserQuestion` 은 자유 응답을 항상 허용하므로 탈출구는 있다.
- **B 를 고르면 `.claude/settings.local.json` 을 건드리지 않는다.** 영구 스위치는 `/dashboard off`
  의 책임이고, 이 선택은 **이번 작업에만** 적용된다.

### 결정 O6 — 검증 어휘는 `MINE`·`FOREIGN`·`SKIP` 3개. 공통 하위 절차로 한 번만 쓴다

`step`·`log`·`impl` 세 절차에 같은 문구를 세 벌 쓰면 하나만 고쳐지는 표류가 생긴다. 「포트 각인」이
이미 공통 하위 절차 방식을 쓰고 있으므로 **그 선례를 따른다.**

| 파일의 `data-owner-token` | 이번 세션의 토큰 | 판정 | 행동 |
|--------------------------|-----------------|------|------|
| 같다 | 있다 | `MINE` | 1단계로 진행 |
| 다르다 | 있다 | `FOREIGN` | **Edit 0회로 중단**하고 보고 |
| 속성 없음 · 빈 문자열 | 있든 없든 | `SKIP` | 진행 + 고지 1줄 |
| 무엇이든 | **없다** | `SKIP` | 진행 + 고지 1줄 |

**마지막 행(내 토큰을 모른다)을 `SKIP` 으로 둔 이유가 중요하다.** 컨텍스트 압축으로 토큰을 잊는 일이
실제로 일어난다. 이때 `FOREIGN` 처럼 중단시키면 **압축 한 번에 대시보드가 영구히 죽는다** — 오늘보다
나쁜 상태다. `SKIP` 은 **오늘과 정확히 같은 동작**에 고지 한 줄을 더한 것이며, 회복 경로(`/dashboard init`
재발행)를 그 고지에 적는다. "어떤 환경에서도 기존 경험을 나쁘게 만들지 않는다"는 「자동 발행」의 원칙과
같은 형태다.

### 결정 O7 — 검증 범위는 `step`·`log`·`impl` 뿐. `serve`·「포트 각인」은 제외한다

| 절차 | 검증 | 근거 |
|------|------|------|
| `step` · `impl set` · `impl <k>` · `log` | **한다** | 파괴적이다. 남의 진행률·상태·로그를 실제로 바꾼다 |
| `init` | **다른 방식으로 한다** | R2 의 0단계가 그 역할이다(토큰이 아직 없는 시점이다) |
| 「포트 각인」 · `serve` | **하지 않는다** | ① 사용자가 명시적으로 부르는 opt-in 이다 ② 바꾸는 것은 `data-server-port` 한 값뿐이고, `old_string` 이 **그 순간 grep 으로 읽은 줄 전문**이라 다른 세션의 상태를 파괴하지 않는다 ③ `serve` 에 검증을 넣으면 "남의 대시보드는 서빙할 수 없다"가 되는데, 그것은 사용자가 원할 수 있는 정당한 동작이다 |
| `on` / `off` | **하지 않는다** | `.claude/settings.local.json` 만 다루며 대시보드 파일에 닿지 않는다 |

### 결정 O8 — 비용: **Bash 호출 0 증가**(`init` 만 +1), Edit `init` +1

| 절차 | Bash | Edit | 비고 |
|------|------|------|------|
| `init` | **+1** (0단계 판정) | **+1** (8단계 토큰 각인) | 세션당 1회뿐인 명령이다 |
| `step` | 0 (기존 grep 에 `-e` 하나 추가) | 0 | 결과가 3줄 → **4줄** |
| `impl set` | 0 (동상) | 0 | 결과 판정 규칙은 아래 GOTCHA 1 |
| `impl <k>` | 0 (동상) | 0 | 결과가 2줄 → **3줄** |
| `log` | **0** | 0 | 0-a 가 이미 그 줄을 읽는다 — **완전 무료** |

세션당 수십 번 불리는 세 경로의 비용이 **한 톨도 늘지 않는다**는 것이 결정 O2 의 실질적 성과다.

## 데이터 모델 / DOM 계약 개정

### 동적(치환 대상) — **6 셀렉터 유지**

셀렉터 표의 행 수는 **바뀌지 않는다.** `#dz-log` 행의 값 칸만 확장한다.

| 셀렉터 | 치환 대상 | 값 |
|--------|----------|-----|
| `#dz-log` | 자식 `<li>` **prepend** + `data-server-port` 속성 + **`data-owner-token` 속성** | 로그 항목(최신이 위) / 서빙 중인 로컬 서버 포트(없으면 빈 문자열) / **이 대시보드를 발행한 세션의 소유 토큰** |

> `data-server-port` 문단 바로 뒤에 놓을 새 문단:
>
> `data-owner-token` 도 새 행이 아니라 `#dz-log` 행의 하위 개념이다 — `data-server-port` 와 **같은
> 줄**에 얹혀 있어야 `step`·`impl` 이 grep 패턴 하나(`-e 'id="dz-log"'`)만 더해 소유권을 확인할 수
> 있고, **Bash 호출은 한 번도 늘지 않는다**. `init` 이 발행 시 **한 번만** 각인하고 `step`·`log`·
> `impl` 은 **읽기만** 한다. 값은 소문자 hex 8자리(`[0-9a-f]{8}`) 또는 빈 문자열이며, **빈 문자열과
> 속성 부재는 같은 뜻**(소유자 미상 — 이 기능 도입 이전에 만들어진 대시보드)이다.

### 불변식 9 (신설 — 기존 1~6, 8에 이어. **7은 결번**이다)

> 9. **`data-owner-token` 은 `init` 만 쓴다. `step`·`log`·`impl` 은 읽기만 하고, 스크립트(폴링·PiP)는
>    읽지도 쓰지도 않는다.** 불변식 8과 같은 이유이며 보호 장치도 같다 — `syncLog` 가 `innerHTML` 만
>    대입하므로 여는 태그의 속성은 폴링 대상이 아니다. 라이브 DOM 의 값이 파일보다 낡아도 무해한
>    이유는, 이 값을 읽는 유일한 주체가 **파일을 직접 grep 하는 오케스트레이터**이기 때문이다.
>    이 속성에 의존하는 JS 를 추가하는 순간 같은 정보의 출처가 둘이 된다.

## 절차 개정안 — `commands/dashboard.md`

아래는 **Edit 단위**로 옮겨 적을 수 있는 형태다. 인용부호 안이 새 문안이다.

### (1) `init` 절 도입 blockquote — 한 문장 추가

기존 blockquote(365~368행) 끝에 덧붙인다. **`이미 존재하면` 이라는 표현을 쓰지 않는다**(GOTCHA 2).

> 다만 **다른 세션이 지금 쓰고 있을 수 있는 대시보드**는 조용히 지우지 않는다 — 0단계가 그 경우만
> 골라내 확인을 받는다. 그 외(파일 없음 · 30분 이상 방치 · 내가 발행한 것)에는 종전과 정확히 같이
> 동작한다.

### (2) `init` 0단계 신설 (기존 1단계 앞)

> 0. **다른 세션이 쓰고 있는 대시보드인지 먼저 판정한다.** Bash 1회. 출력 첫 줄은 폐쇄 어휘 3개
>    중 하나이며, 파일이 있으면 참고 정보 1~2줄이 뒤따른다.
>
>    ```bash
>    if [ ! -f .claude/dashboard.html ]; then echo ABSENT; else
>      if [ -n "$(find .claude/dashboard.html -mmin -30)" ]; then echo RECENT; else echo STALE; fi
>      grep -o -e 'data-owner-token="[^"]*"' -e 'id="dz-title">[^<]*' .claude/dashboard.html || true
>    fi
>    ```
>
>    - `30` 은 허브의 `stale_after_minutes` 기본값과 같은 값이다. 두 도구가 "활동 중"을 다른 숫자로
>      판정하면 화면과 프롬프트가 어긋난다.
>    - 2번째 줄부터는 **순서와 무관하게 접두어로 식별한다**(`data-owner-token="` / `id="dz-title">`).
>      토큰 줄이 없으면 이 기능 도입 이전에 만들어진 대시보드다.
>    - **`|| true` 를 지우지 않는다** — 토큰이 없는 대시보드에서 `grep` 이 종료 코드 1을 내
>      명령 전체가 실패로 보인다.
>    - 위 셋이 아닌 출력이 나오거나 명령이 실패하면 **추측하지 말고 `RECENT` 로 본다**(안전한 쪽).
>
>    | 첫 줄 | 파일의 토큰 | 행동 |
>    |------|-----------|------|
>    | `ABSENT` | — | 1번으로. 묻지 않는다 |
>    | `STALE` | 무엇이든 | 1번으로. 묻지 않는다 |
>    | `RECENT` | 이번 세션이 각인한 토큰과 **같다** | 1번으로. 묻지 않는다 — 같은 세션의 다음 작업이다 |
>    | `RECENT` | 다르다 · 없다 · 이번 세션에 토큰이 없다 | **아래 확인 절차로 간다** |
>
>    **확인 절차** — `AskUserQuestion` 도구가 있으면 선택지 2개로 묻고, 없으면 같은 내용을 평문으로
>    묻고 답을 기다린다. **묻기 전에 아무것도 지우지 않는다.**
>
>    - 질문: "`.claude/dashboard.html` 이 30분 이내에 갱신됐습니다 — 다른 메인 세션이 사용 중일 수
>      있습니다(현재 제목: 「{제목}」). 어떻게 할까요?"
>    - **덮어쓰기**: 기존 대시보드를 지우고 이번 작업으로 새로 발행합니다. 그 세션의 진행 상태와
>      작업 추적 로그는 남지 않습니다.
>    - **대시보드 없이 진행**: 이번 작업에서는 대시보드를 만들지 않습니다. 기존 파일을 그대로 두고,
>      이후 `step`·`log`·`impl` 호출도 생략합니다. 앞으로 계속 끄려면 `/dashboard off` 를 쓰세요.
>
>    「덮어쓰기」 → 1번으로 진행한다.
>    「대시보드 없이 진행」 → **절차를 여기서 끝낸다.** 파일을 만들지도 지우지도 않고, 이번 작업
>    동안 `/dashboard` 하위 명령을 더 부르지 않는다. `.claude/settings.local.json` 은 **건드리지
>    않는다** — 영구 스위치는 `/dashboard off` 의 책임이다.

### (3) `init` 1단계 Bash 교체 + 설명 2줄

> ```bash
> mkdir -p .claude && rm -f .claude/dashboard.html && od -An -N4 -tx1 /dev/urandom | tr -d ' \n' && echo
> ```
> `mkdir -p` 도 `rm -f` 도 대상이 없을 때 조용히 성공하므로 존재 확인이 필요 없다. **이 제거를
> 생략하지 않는다** — Write 도구는 이 세션에서 읽지 않은 기존 파일을 덮어쓰지 못한다. 먼저 지우면
> Write 는 언제나 "새 파일 생성"이 되어 절차가 결정적이다.
>
> 마지막 출력 8글자(`[0-9a-f]{8}`)가 **이번 세션의 소유 토큰**이다. 대화 컨텍스트에 기억하고,
> 8단계에서 파일에 각인하며, 10단계 보고에 한 줄 적는다. `/dev/urandom` 은 어디에나 있고 `od`·`tr`
> 은 POSIX 유틸리티다 — `python3`·`openssl` 에 의존하지 않는다(둘 다 없을 수 있는 환경을 이 문서는
> 이미 정상 경로로 다룬다).

### (4) `init` 8단계 교체 (**"Edit 하지 않는다" 문구가 사라진다** — GOTCHA 3)

> 8. **소유 토큰을 각인한다.** `#dz-log` 는 여전히 **빈 목록**이며 자식은 건드리지 않는다.
>    템플릿의 아래 줄을 `old_string` 으로 Edit 1회.
>    ```html
>    <ul class="log" id="dz-log" data-owner-token="" data-server-port=""></ul>
>    ```
>    → `data-owner-token` 값만 1단계에서 얻은 토큰으로 채운다.
>    각인에 실패해도 `init` 을 중단하지 않는다 — 이후 `step`·`log`·`impl` 이 전부 `SKIP` 판정으로
>    떨어질 뿐 기능은 동작한다(「자동 발행」과 같은 실패 비차단 원칙). 다만 그 사실을 보고에 남긴다.

### (5) `init` 10단계 보고 — 한 줄 추가

> 보고에 소유 토큰을 한 줄 적는다: "소유 토큰 `{토큰}` — 이 세션이 발행한 대시보드입니다."
> (0단계에서 「대시보드 없이 진행」을 골랐다면 대신 "이번 작업은 대시보드를 만들지 않습니다 —
> 기존 대시보드를 그대로 두었습니다"만 보고하고 끝낸다.)

### (6) 「소유권 검증」 공통 하위 절차 신설

`step` 절 바로 앞에 새 절로 넣는다(「포트 각인」이 공통 하위 절차로 놓인 방식과 같다).

> ## 소유권 검증 — `step` · `log` · `impl` 의 공통 0단계
>
> 입력은 각 절차의 0단계 grep 이 이미 가져온 **`#dz-log` 여는 태그 전문** 하나다. **Bash 호출을
> 새로 만들지 않는다.** 판정은 폐쇄 어휘 3개다.
>
> | 파일의 `data-owner-token` | 이번 세션의 토큰 | 판정 | 행동 |
> |--------------------------|-----------------|------|------|
> | 같다 | 있다 | `MINE` | 그대로 1단계로 진행한다 |
> | 다르다 | 있다 | `FOREIGN` | **어떤 Edit 도 하지 않고 중단한다** |
> | 속성 없음 · 빈 문자열 | 있든 없든 | `SKIP` | 진행하되 보고에 한 줄 덧붙인다 |
> | 무엇이든 | **없다**(이 세션이 `init` 을 부르지 않았거나 토큰을 잃었다) | `SKIP` | 위와 같다 |
>
> - `FOREIGN` 보고: "이 대시보드는 다른 세션이 발행한 것입니다(파일 `{파일값}` ≠ 내 `{내값}`).
>   내 대시보드가 다른 세션의 `init` 으로 대체됐습니다 — **이번 갱신은 수행하지 않았습니다.**
>   계속 기록하려면 `/dashboard init` 으로 새로 발행하십시오(그 세션의 대시보드는 사라집니다)."
> - `SKIP` 보고: "소유 토큰이 없어 소유권을 확인하지 못했습니다 — 갱신은 수행했습니다."
>   (내 토큰을 잃은 경우라면 `/dashboard init` 재발행으로 회복된다는 한 줄을 덧붙인다.)
> - **`FOREIGN` 에서 다른 파일·다른 셀렉터를 찾아보지 않는다.** 이 판정의 목적은 **조용한 오염을
>   감지된 중단으로 바꾸는 것 하나**뿐이다. 복구는 사용자가 정한다.

### (7) `step` 0단계

> ```bash
> grep -n -e 'id="dz-cell-{g}-{p}"' -e 'id="dz-progress-bar"' -e 'id="dz-progress-pct"' -e 'id="dz-log"' .claude/dashboard.html
> ```
> (선형 모드면 첫 패턴을 `id="dz-step-{n}"` 로 바꾼다.)
> 각 요소는 한 줄에 하나씩 생성되므로 **결과는 항상 4줄이다**(대상 1 + 진행률 2 + 소유 토큰 1).
> 마지막 패턴은 **소유권 검증 전용**이며 Bash 호출을 늘리지 않는다. 이 줄로 위
> 「소유권 검증」을 수행하고, `FOREIGN` 이면 **1~3단계를 전부 생략하고 중단한다.**

### (8) `impl set` 0단계 (**개수 판정 표는 무수정** — GOTCHA 1)

> ```bash
> grep -n -e 'id="dz-log"' -e 'id="dz-impl-tasks"' -e 'id="dz-impl-count"' -e 'id="dz-impl-1"' .claude/dashboard.html
> ```
> `id="dz-log"` 줄은 **어떤 대시보드에도 항상 1줄** 매칭된다. 이 줄로 위 「소유권 검증」을 먼저
> 수행하고(`FOREIGN` 이면 중단), **아래 표의 개수는 그 줄을 뺀 나머지**로 센다.
> (기존 3줄 / 2줄 / 0~1줄 분기표는 그대로 둔다.)

### (9) `impl <k>` 0단계

> ```bash
> grep -n -e 'id="dz-impl-{k}"' -e 'id="dz-impl-count"' -e 'id="dz-log"' .claude/dashboard.html
> ```
> 각 요소는 한 줄에 하나씩 생성되므로 **결과는 항상 3줄이다.** 마지막 줄로 위 「소유권 검증」을
> 수행하고, `FOREIGN` 이면 1~3단계를 생략하고 중단한다.

### (10) `log` 0-a — grep **무변경**, 문장 2줄 추가

> 이 줄의 `data-owner-token` 값으로 위 「소유권 검증」을 수행한다. **grep 을 추가하지 않는다 —
> 이미 읽은 줄이다.** `FOREIGN` 이면 1·2·3단계를 전부 생략하고 중단한다(`commit` 인자여도 서버를
> 끄지 않는다 — 그 서버는 다른 세션의 것이다).

### (11) 「포트 각인」 하위 절차 — 보존 1줄 추가

> 이 절차는 `data-owner-token` 을 **읽지도 바꾸지도 않는다.** `old_string` 이 1번에서 읽은 줄
> 전문이므로 토큰은 그대로 보존된다(불변식 9).

### (12) 템플릿 전문 — 2줄

**`#dz-log` 줄**
```html
    <ul class="log" id="dz-log" data-owner-token="" data-server-port=""></ul>
```

**헤더 주석 맵의 `#dz-log` 항목**에 2줄 추가:

```
  #dz-log               : 작업 추적 ul — li data-seq 앵커로 prepend / data-server-port 속성(…기존…)
                          / data-owner-token 속성(이 대시보드를 발행한 세션의 소유 토큰. init 만
                            각인하고 step·log·impl 은 읽기만 한다 — 스크립트는 건드리지 않는다)
```

## GOTCHA (구현 중 반드시 확인)

1. **`impl set` 0단계의 개수 판정을 +1 시프트하지 마라.** 그 표(3줄=이미 있음 / 2줄=정상 /
   0~1줄=구세대)는 **분기 결정 규칙**이지 설명문이 아니다. `id="dz-log"` 는 항상 1줄 매칭되므로
   "그 줄을 뺀 나머지로 센다" 문장 하나만 추가하고 **표는 손대지 않는다.** 표의 숫자를 4/3/1~2 로
   고치는 것이 가장 그럴듯한 잘못된 구현이다(둘 다 동작은 하지만, 표를 고치면 이 문서의 다른
   서술·테스트와 어긋난다).
2. **`init` 0단계 문안에 `이미 존재하면` 을 쓰지 마라.** `tests/run.sh` T22-93 이 `init` 절 범위에서
   그 문자열의 **부재**를 검사한다(세션 재사용 분기가 되살아나는 회귀 방지). "존재하고 최근에
   갱신됐으며 남의 토큰일 때"처럼 다르게 쓴다.
3. **`init` 8단계의 "**Edit 하지 않는다.**" 문구를 반드시 지워라.** 남겨 두면 구현자가 각인을
   건너뛰고, 토큰이 영원히 빈 문자열이 되어 **R3 전체가 `SKIP` 으로 죽는다.** T22-106 이 역방향으로
   막는다.
4. **토큰을 `#dz-title`·`#dz-updated`·`#dz-progress-pct` 에 붙이지 마라.** `hub_parse.py` 의
   정규식이 `<h1 id="dz-title">`·`id="dz-updated">` 처럼 **닫는 꺾쇠까지 완전 일치**다. 속성을
   끼우는 순간 `parse_dashboard_html` 이 `None` 을 돌려 **허브 티어 1이 통째로 사라진다.**
5. **스크립트에 토큰을 읽는 코드를 넣지 마라.** 불변식 9 위반이고, 동시에 grep 유일성 불변식도
   위험해진다(스크립트가 `id="dz-log"` 문자열을 만들면 `log` 0-a 가 2줄을 받는다). T22-109 가
   `getAttribute('data-owner-token')`·`dataset.ownerToken` 의 부재를 검사한다.
6. **`|| true` 와 `$( )` 를 유지하라.** `|| true` 가 없으면 토큰 없는 대시보드에서 명령 전체가
   종료 코드 1로 보이고, `$(find …)` 의 명령 치환은 이 판정의 핵심이다(다른 Bash 블록의
   "`$` 를 쓰지 않는다" 규칙은 **`python3 -c` 안의 파이썬 코드**에 대한 것이다 — 셸 구문에는
   적용되지 않는다).
7. **토큰 각인(8단계)은 「자동 발행」(9단계)보다 **먼저**다.** 「자동 발행」 2단계는 파일 바이트를
   읽어 서버 응답과 비교하고(`got == mine`), 3단계는 같은 줄을 Edit 한다(포트 각인). 각인을 뒤로
   미루면 같은 줄에 대한 Edit 이 겹쳐 앵커가 흔들린다. **순서를 바꾸지 마라.**
8. **`data-server-port` 와 이름이 겹치는 속성을 만들지 마라.** `log commit` 3-c 는
   `data-server-port="{포트}"` 문자열의 **문서 내 유일성**에 기대 줄 전문을 다시 읽지 않는다.
   `data-owner-token` 은 부분 문자열이 겹치지 않는다(확인함) — 이 성질을 유지하라.

## 검토했으나 채택하지 않은 대안

1. **락 파일(`.claude/dashboard.lock`) + `flock`** — **거부.** 새 상태 파일이 생겨 전제 3을 깨고,

   **조용한 오염**이며, 그것은 토큰 비교 한 번으로 감지된다.
2. **`init` 이 기존 대시보드를 백업(`dashboard.html.bak-{시각}`)한 뒤 덮어쓴다** — **거부.**

   미해결로 남는다.
3. **`step`·`log`·`impl` 이 토큰 불일치 시 "내 대시보드를 다시 만들어" 복구한다** — **거부.**
   자동 복구가 상대 세션의 대시보드를 또 지운다. 두 세션이 서로를 덮어쓰는 **핑퐁**이 되고,
   그 상태는 지금보다 훨씬 나쁘다. 감지하고 멈추는 것이 정답이다.
4. **토큰 대신 `#dz-title` 텍스트(세션 제목)를 비교** — **거부.** 제목이 같은 두 작업이 흔하고
   (`재시도`·`리팩토링`), 무엇보다 `hub_parse` 정규식이 그 줄을 완전 일치로 읽고 있어 형식 변경
   여지가 없다.
5. **`#dz-updated` 텍스트로 신선도 판정** — 결정 O3 에서 3가지 근거로 기각(파싱 산술·분해능·출처 이중화).
6. **확인 선택지에 "다른 이름으로 저장" 추가** — **거부(YAGNI).** 안 1의 파일 분리를 절반만

   **아무도 보지 않는 대시보드**가 만들어진다. 파일 분리는 허브 확장과 함께여야 의미가 있다(R4).
7. **`init` 에 `--force` 플래그를 추가해 확인을 건너뛴다** — **거부(YAGNI).** 확인이 뜨는 경우가
   이미 드물게 설계돼 있다(결정 O4). 인터페이스를 늘리지 않는다.

> **해소(2026-09-02, hub-session-tree-and-per-session-dashboards.md)** — 안 1 을 채택했다. 파일명은
> 토큰이 아니라 세션 ID 다(**보류 근거 2 무효**, ST1). 토큰은 SESSION 모드에서 세션 ID 앞 8자리로
> 남는다(ST3). 보류 근거 3·4 는 §8·ST5 가 답했다. 재방문 트리거는 **T-4**(허브가 이미 세션 단위
> 표시로 확장된다)가 발화했다.

### (a) 안 1의 개요와 안 2 대비 추가로 얻는 것

**개요.** 대시보드를 프로젝트당 1파일에서 **세션당 1파일**로 쪼갠다.

```
.claude/dashboards/<토큰>.html      # 세션마다 하나. init 이 만들고 세션이 끝나면 남는다
```

- `init` 은 파일을 지우지 않는다 — **애초에 남의 파일을 건드릴 일이 없다.**
- `step`·`log`·`impl` 은 자기 토큰으로 만든 **경로**를 연다. 토큰 비교가 아니라 **경로 자체가
  소유권**이다.
- 허브는 `.claude/dashboards/` 를 순회해 **세션 목록**을 수집하고, registry 를 `(프로젝트, 세션)`
  단위로 확장하며, 카드 모달이 세션 선택 UI 를 갖는다.

**안 2 대비 추가로 얻는 것 — 정확히 셋이다.**

| # | 얻는 것 | 안 2 에서는 |
|---|--------|------------|
| 1 | **덮어쓰기가 원리적으로 불가능**하다. 확인 프롬프트 자체가 사라진다 | 확인으로 완화. `STALE` 오판 구간은 남는다(E2) |
| 2 | **두 번째 세션의 진행률이 허브에서 보인다.** 지금은 마지막 `init` 세션만 보인다(문제 ③) | 해결되지 않는다 — **의도적으로 범위 밖이다** |
| 3 | **토큰 망실이 덜 치명적**이다. 파일명이 곧 토큰이라 `ls` 로 되찾을 수 있다 | `SKIP` 으로 열화(리스크 2) |

### (b) 지금 도입하지 않는 이유 (YAGNI)

1. **같은 프로젝트에서 동시에 전체 경로 작업을 두 개 돌리는 일이 드물다.** 대시보드는 기능 단위로
   만들고 끝나면 지우는 임시 산출물이며(전제 1), 실제 사용 패턴은 순차적이다. 안 2 는 그 드문 경우를
   **안전하게** 만들고, 안 1 은 그 드문 경우를 **편하게** 만든다 — 지금 필요한 것은 안전이다.
2. **메인 세션이 자기 세션 ID 를 아는 표준 수단이 없다.** 그래서 안 1도 결국 **별도 토큰 체계**를
   요구한다 — 즉 안 1은 안 2 의 상위집합이지 대체재가 아니다. 토큰 없이 안 1만 하는 길은 없다.
3. **영향 범위가 크다.** 허브의 수집(`hub_collect.py` 의 `PROJECT_DASHBOARD_RELATIVE_PATH` 고정 경로),
   registry(`build_dashboard_registry`), 서버 라우트 정규식(`^/project/([0-9a-f]{16})/dashboard\.html\Z`),
   카드 모달 UI, 그리고 그 전부의 파이썬·셸 테스트가 함께 움직인다. **이번 변경이 "허브 코드 한 줄도
   바꾸지 않는다"는 것과 정반대다.**
4. **파일 수명 관리 문제가 새로 생긴다.** 세션당 1파일이면 누가 언제 지우는가? 리텐션 규칙·정리
   명령·`.gitignore` 패턴이 따라온다. 지금은 `rm .claude/dashboard.html` 하나로 끝난다.

### (c) 재방문 트리거 (아래 중 하나가 관측되면 안 1을 다시 검토한다)

| # | 신호 | 왜 이것이 신호인가 |
|---|------|-------------------|
| T-1 | 같은 프로젝트의 **동시 전체 경로 작업이 일상**이 되고, **두 번째 세션의 단계 진행률을 허브에서 봐야** 한다 | 안 2 가 원리적으로 못 주는 것(위 (a)-2)이 필요해진 시점이다 |
| T-2 | 결정 O5 의 **덮어쓰기 확인이 반복적으로 걸리적거린다** | 결정 O4 로 흔한 경우를 이미 제거했음에도 자주 뜬다면, 진짜로 동시 작업이 일상이 된 것이다(T-1 의 선행 지표) |
| T-3 | `FOREIGN` 중단 보고가 **주 단위로 반복** 관측된다 | R3 가 잡고는 있지만 손실(A 의 대시보드)이 실제로 계속 발생하고 있다는 뜻이다 |
| T-4 | 허브가 이미 **세션 단위 표시**로 확장된다(다른 요구로) | 안 1의 영향 범위 중 가장 큰 조각이 이미 지불된 상태가 된다 |

### 연결점 — 안 2 의 토큰은 안 1 의 파일 명명 체계로 **그대로 확장된다**

이번에 도입하는 토큰은 **8자리 hex 이고 `init` 이 1회 생성한다.** 안 1로 넘어갈 때:

- 파일 경로가 `.claude/dashboards/{토큰}.html` 이 된다 — **토큰 생성 로직(결정 O1)을 그대로 쓴다.**
- `data-owner-token` 각인은 **남겨 둔다.** 경로와 파일 내용이 서로를 검증하고, 허브가 파일을
  열어 세션을 식별할 때 파일명 파싱 없이 속성 하나로 끝난다.
- `step`·`log`·`impl` 의 「소유권 검증」은 **경로 결정 규칙으로 대체**된다(검증이 사라지는 것이
  아니라 더 강한 형태로 승격된다).

즉 이번 라운드는 안 1의 **선행 조건을 미리 지불하는 형태**이며, 버려지는 자산이 없다.

## 사용자 승인이 필요한 결정

### 승인 항목 1 — 토큰을 `#dz-log` 여는 태그에 둔다 (결정 O2)

허브 파서(`hub_parse.py`)가 `#dz-title`·`#dz-updated`·`#dz-progress-pct` 를 **닫는 꺾쇠까지 완전
일치**로 읽는다는 것을 직접 확인했다. `#dz-log` 는 허브가 유일하게 읽지 않는 동적 셀렉터이며,
`log` 가 이미 매번 grep 하는 줄이라 검증 비용이 **0**이다.
**대안**: `<head>` 의 `<meta>` — 허브를 깨지는 않지만 세 절차에 새 grep 대상이 하나 늘고 얻는 것이 없다.

### 승인 항목 2 — "최근"은 **파일 mtime 30분**으로 판정한다 (결정 O3)

허브 `stale_after_minutes` 기본값과 같은 값을 쓴다. **이 임계값은 완전하지 않다** — 40분간 대시보드를
갱신하지 않는 긴 구현 단계는 `STALE` 로 오판된다. 그 구멍은 R3(토큰 검증)가 받으며, 결과는
"조용한 오염"이 아니라 "감지된 중단"이다.
**대안**: `#dz-updated` 텍스트 파싱(같은 정보의 출처가 둘이 된다) · 60분 이상(확인 프롬프트가 늘어난다).

### 승인 항목 3 — 같은 세션의 재발행은 **묻지 않는다** (결정 O4)

`RECENT` 여도 파일의 토큰이 **내 토큰이면** 조용히 재생성한다. 한 세션이 기능 A 를 끝내고 곧바로
기능 B 를 시작하는 가장 흔한 흐름에서 프롬프트가 뜨지 않게 하는 결정이다.
**대안**: mtime 만으로 판정(구현은 더 단순하지만 정상 흐름마다 묻는다).

### 승인 항목 4 — 토큰을 모를 때는 **중단하지 않고 진행**한다 (`SKIP`, 결정 O6)

컨텍스트 압축으로 토큰을 잊은 세션, 그리고 이 기능 이전에 만들어진 대시보드는 `SKIP` 으로 처리해
**오늘과 똑같이 동작**하고 고지 한 줄만 덧붙인다. 여기서 중단시키면 압축 한 번에 대시보드가
영구히 죽어 오늘보다 나쁜 상태가 된다.
**대안**: `SKIP` 도 중단(보호는 강해지지만 정상 사용을 깨뜨린다).

### 승인 항목 5 — 확인 선택지는 **2개**, `serve` 는 검증하지 않는다 (결정 O5·O7)

「덮어쓰기」/「대시보드 없이 진행」 둘뿐이며, 후자는 `.claude/settings.local.json` 을 건드리지 않고
**이번 작업에만** 적용된다(영구 스위치는 `/dashboard off`). `serve`·「포트 각인」은 파괴적이지 않고
사용자가 명시적으로 부르는 opt-in 이므로 검증 대상에서 뺀다.
**대안**: 선택지 3개("다른 이름으로 저장" — 안 1의 절반 도입이라 아무도 보지 않는 대시보드가 생긴다).
