# 대시보드 자동 발행 — `init` 이 서버를 띄우고 브라우저를 연다 (PRP)

## 요구사항 요약

`/dashboard init` 은 현재 `.claude/dashboard.html` 을 만들고 **`file://` 경로 문자열 한 줄을
출력하는 것으로 끝난다.** 사용자는 그 문자열을 손으로 복사해 브라우저에 붙여넣어야 하고,
그렇게 연 화면은 `file://` 모드라 **창에 포커스가 갈 때만** 갱신되며 플로팅(Document PiP)
버튼도 비활성이다. 살아 있는 갱신과 플로팅을 쓰려면 `/dashboard serve` 를 따로 불러야 하는데,
이건 존재를 아는 사람만 부르는 opt-in 이다.

이번 요청은 **"발행 시 서버를 띄우고 자동으로 브라우저에 보이게"** 다. 즉 `init` 한 번으로
(1) 로컬 정적 서버가 뜨고 (2) 브라우저가 열려 (3) 그 뒤로는 5초 폴링으로 저절로 갱신되는
상태까지 도달해야 한다. 손으로 할 일이 0이 되는 것이 이 라운드의 유일한 성공 기준이다.

다만 이 기능은 **환경마다 가능 여부가 다르다.** `commands/dashboard.md` 는 코드가 아니라
`~/.claude/commands/` 에 전역 설치되어 **여러 프로젝트·여러 실행 환경의 메인 세션이 읽고
따르는 절차 문서**다. 브라우저를 여는 수단도, python3 의 존재도, 포트의 여유도 환경 상수가
아니다. 따라서 이 설계의 절반은 **"되면 하고 안 되면 조용히 내려앉는 사다리"** 를 자연어
판정 기준으로 정확히 못 박는 일이다.

### 워크플로우 경로 판정 (스스로 재확인)

전역 CLAUDE.md 의 분류 기준에 비춰 **전체 경로가 맞다.** 근거:

| 기준 | 해당 여부 | 근거 |
|------|----------|------|
| 새 모듈/레이어 추가, 디렉토리 구조 변경 | ✕ | 새 파일 없음. 새 하위 명령도 없다 |
| 데이터 모델·공개 인터페이스 변경 | △ | 셀렉터 계약·호출 규약은 **한 글자도 안 바뀐다.** 다만 `init` 의 **관측 가능한 부작용**(프로세스 기동·브라우저 실행)이 바뀐다 |
| **3개 이상 파일에 걸친 로직 변경** | **○** | `commands/dashboard.md` · `tests/run.sh` · `README.md` |
| 새 외부 의존성 도입 | ✕ | `python3` 은 `serve` 가 이미 요구한다. curl 등 신규 의존성 없음 |
| **민감 영역** | **○(경계)** | 사용자 머신에서 **백그라운드 프로세스를 띄우고 네트워크 포트를 연다.** 데이터 삭제·인증은 아니지만 "조용히 리소스를 점유하는 기본 동작"이라 승인 없이 넣을 성질이 아니다 |

3번 단독으로도 전체 경로다. 5번(포트·프로세스)이 겹치므로 **설계 승인 없이 구현하지 않는다.**

### 사용자와 합의된 확정 사항 (재논의 대상 아님)

1. **`init` 이 서버를 띄운다.** opt-in `serve` 를 부르라고 안내하는 것으로는 요구를 만족하지 못한다.
2. **브라우저가 자동으로 열린다.** URL 출력만으로는 요구를 만족하지 못한다.
3. **`step`·`log`·`impl` 은 이 라운드에서 한 글자도 바뀌지 않는다.** 세션 중 수십 번 불리는
   명령이 서버를 재기동하거나 탭을 다시 여는 일은 없다.

### 이 PRP 의 위치 — 선행 라운드와의 관계

| 라운드 | 산출 | 이번 라운드와의 접점 |
|--------|------|---------------------|
| `session-dashboard.md` | `init`/`step`/`log`, 셀렉터 계약, "서브에이전트는 파일에 접근하지 않는다" | `init` 절차 1·10단계를 이번에 고친다 |
| `dashboard-pip-floating.md` | `serve` 하위 명령, `UpdateMode`(protocol 판정), PiP 버튼 | **`serve` 의 기동 명령을 그대로 재사용한다.** `http://` 모드 폴링·PiP 활성화가 이번 기능의 실질적 보상이다 |
| `dashboard-group-matrix.md` | 매트릭스 렌더링 | 접점 없음 |
| `dashboard-impl-substeps.md` | `impl` 패널 | 접점 없음 |
| `dashboard-current-next-card.md` (직전, 미커밋) | 「지금」 카드, `data-started-at` | 접점 없음. **다만 미커밋 상태의 `commands/dashboard.md`·`tests/run.sh`·`README.md` 를 이어서 수정하므로, 구현 착수 전 그 변경이 커밋됐거나 최소한 안정 상태인지 확인한다** |

**핵심 관찰**: PiP 라운드가 이미 `serve` 로 "http 로 띄우는 법"을 확립해 뒀고, 템플릿 스크립트는
이미 `location.protocol` 로 폴링/리로드를 가른다. 이번 라운드는 **없던 것을 만드는 게 아니라
이미 있는 두 조각을 `init` 이 자동으로 잇게 하는 것**이다. 그래서 템플릿(HTML/CSS/JS)은 한 줄도
바뀌지 않는다 — 이것이 이 설계의 가장 중요한 성질이며, 리스크 대부분이 여기서 제거된다.

### 사용자 스토리

```
As a  전체 경로 작업을 시작하는 개발자
I want /dashboard init 한 번으로 대시보드가 브라우저에 떠 있는 상태가 되기를
So that URL 복사·붙여넣기와 「왜 화면이 안 바뀌지」(file:// 포커스 갱신)에서 해방된다
```

### 복잡도

| 항목 | 평가 |
|------|------|
| 코드(템플릿 HTML/CSS/JS) 변경 | **0줄** |
| 절차 문서 변경 | `init` 1·10단계 재작성 + 새 하위 절 1개 (~90줄) |
| 새 하위 명령 | **없음** (`serve` 는 그대로 둔다) |
| 새 셀렉터·새 인자·새 설정 키 | **없음** (설정 키는 승인 결정 5 참조) |
| 새 외부 의존성 | 없음 |
| 자동 검증 가능 비율 | 낮음 — **런타임 동작(포트 바인딩·브라우저 실행)은 `tests/run.sh` 로 검증 불가.** 문서 정합성만 정적 검증하고 나머지는 수동 확인으로 분리한다 |

## 스코프와 비목표

### 스코프 안

1. `init` 절차 **10단계 재작성** — `file://` 출력을 「자동 발행」 하위 절차 호출로 바꾸고,
   `file://` 출력은 **폴백 티어**로 살려 둔다.
2. `init` 절차 **1단계 기존-파일 분기 재작성** — 조기 종료 직전에 같은 「자동 발행」을 호출한다.
3. 새 하위 절 **「자동 발행 — `init` 의 공통 하위 절차」** 신설. 서버 재사용·포트 스캔·브라우저
   열기·폴백 사다리를 여기 한 곳에만 쓴다(두 분기가 참조).
4. `serve` 5단계에 **브라우저 열기 하위 절차 호출 1줄** 추가 (승인 결정 4).
5. `tests/run.sh` T22 에 정적 검증 **T22-68 ~ T22-79** 추가.
6. `README.md` `/dashboard` 문단 1~2문장 갱신 + 커맨드 표의 줄 수 갱신.

### 비목표 (명시적으로 만들지 않는 것)

| 안 만드는 것 | 이유 |
|-------------|------|
| **새 하위 명령**(`/dashboard open` 등) | `init` 안에 흡수된다. 규약이 늘면 `argument-hint` 가 또 길어지고, 사용자가 외울 것이 늘어난다 |
| **세션 종료 훅으로 서버 자동 종료** | `commands/*.md` 는 훅을 설치할 권한이 없다. `settings.json` 의 `Stop` 훅은 **턴 종료마다** 불려 세션 종료와 의미가 다르다. 잘못된 도구다 |
| **`nohup`/`setsid` 로 프로세스 분리** | 정반대로 가야 한다. 세션에 매인 수명이 **바람직한 기본값**이다(리스크 3 참조) |
| **포트를 `.claude/` 어딘가에 기록** | 상태 파일을 두지 않는다는 원설계 원칙 위반(`session-dashboard.md`). 포트는 매번 **탐지**한다 |
| **HTTPS·인증·외부 접근** | `--bind 127.0.0.1` 로 루프백 고정. 원격 공유는 이 도구의 목적이 아니다 |
| **브라우저 자동 설치·MCP 서버 자동 설정** | 없는 수단을 만들어내지 않는다. 있으면 쓰고 없으면 내려앉는다 |
| **`serve` 의 "명시 포트는 추측 재시도 금지" 규칙 완화** | 사용자가 포트를 지정한 호출을 몰래 다른 포트로 옮기지 않는다. 스캔은 **자동 경로 전용**이다 |
| **파일 변경 감시(watch) 기반 push** | 폴링 5초로 충분하다. SSE/WebSocket 은 `python3 -m http.server` 로 불가능하고 새 의존성을 부른다 |

## UX 전환

### Before

```
사용자: (전체 경로 작업 착수)
메인 세션: /dashboard init "…" "설계|구현|검수"
출력:      file:///Users/me/proj/.claude/dashboard.html  ← 손으로 복사
사용자:    (복사 → 브라우저 주소창 → 붙여넣기 → Enter)
이후:      step/log 가 파일을 고쳐도 화면은 그대로.
           창을 클릭해 포커스를 줘야 리로드된다.
           우상단 「플로팅」 버튼은 비활성 (file:// 이므로).
사용자:    (플로팅 쓰려면) /dashboard serve → 다시 URL 복사 → 붙여넣기
```

### After

```
사용자: (전체 경로 작업 착수)
메인 세션: /dashboard init "…" "설계|구현|검수"
           → 대시보드 파일 생성
           → 8791~8793 스캔: 이 프로젝트용 서버가 이미 있나? 없으면 빈 포트에 기동
           → 브라우저 열기 (도구 → OS 명령 → 포기, 순서대로)
출력:      http://localhost:8791/dashboard.html (자동으로 열었습니다 · 5초마다 갱신됩니다)
           끝나면 /dashboard serve stop 8791
사용자:    (아무것도 안 함. 이미 화면에 떠 있고 저절로 바뀐다)
```

| `http://localhost`·`http://127.0.0.1` 은 **secure context** 로 취급된다 (W3C "potentially trustworthy origin") | W3C Secure Contexts | `documentPictureInPicture` 가 평문 http 로도 동작한다. TLS 를 만들 필요가 없다 |
| `python3 -m http.server` 는 심볼릭 링크를 따라간다 | 기존 `serve` 가 이미 이 성질에 의존 | 임시 디렉토리 + 링크 1개 구조를 그대로 재사용 |
| `socket.connect_ex()` 는 예외 없이 errno 를 반환한다(0 = 연결 성공 = 포트 점유) | Python 표준 | **동기적·결정적 포트 점유 판정**을 새 의존성 없이 얻는다 |
| macOS 의 `open`, 대부분 Linux 데스크톱의 `xdg-open` 이 기본 브라우저를 연다 | OS 표준 | 브라우저 도구가 없는 순수 터미널 세션에서도 자동 열기가 **가능하다** — 이 설계의 전제를 뒤집는 사실이다 |
| macOS 에서 SSH 로 접속해 `open` 을 실행하면 **원격 머신의 콘솔**에서 열린다 | 널리 알려진 동작 | `$SSH_CONNECTION` 이 있으면 시도 자체를 하지 않는다 |

> **설계상 가장 중요한 발견**: "순수 터미널 세션에는 브라우저를 여는 수단이 없다"는 전제는
> **틀렸다.** Bash 가 있으면 `open`/`xdg-open` 이 있다. 따라서 브라우저 도구(Browser pane, MCP)는
> **1순위 수단이 아니라 있으면 좋은 대안**이고, 이식성의 주축은 OS 열기 명령이다.
> 이 사실 하나로 "환경마다 다르다"는 난제의 대부분이 사라진다.

## 데이터 모델

이 기능은 DOM 계약을 만들지 않는다. 대신 **절차 안에서만 흐르는 3개의 값**이 있다. 이 표가
「자동 발행」 하위 절차의 입출력 계약이다.

### 개념 모델

```
PublishTarget                        # 자동 발행이 최종적으로 확정하는 것
  url        : string                # 사용자에게 출력하고 브라우저에 넘길 URL
  tier       : "served" | "file"     # http:// 로 발행했는가, file:// 로 내려앉았는가
  port       : int | null            # tier == "served" 일 때만 존재
  started    : bool                  # 이번 호출이 서버를 새로 띄웠는가 (재사용이면 false)

PortScanResult                       # 포트 스캔 Bash 1회의 출력 (아래 3형태 중 하나)
  "<포트> REUSE"                     # 그 포트에 이 프로젝트의 대시보드가 이미 떠 있다
  "<포트> FREE"                      # 그 포트가 비어 있다 → 여기에 띄운다
  "NONE"                             # 후보 포트가 전부 남의 것이다

OpenOutcome                          # 브라우저 열기 시도의 결과
  "opened"   | "skipped"             # 열었다 | 열 수단이 없어 시도하지 않았다
```

- **`PortScanResult` 가 이 설계의 유일한 계약이다.** 문자열 3형태에 판정을 모두 몰아넣어,
  메인 세션이 `ps` 출력을 해석하거나 에러 메시지를 분류하는 **추론 작업을 하지 않게 한다**
  (`step` 이 grep 결과 3줄만 보고 결정적으로 움직이는 것과 같은 설계다).
- **상태를 파일에 남기지 않는다.** 포트는 매 `init` 마다 스캔으로 다시 알아낸다.
  `session-dashboard.md` 의 "별도 상태 파일(JSON)은 두지 않는다" 원칙을 그대로 지킨다.

### 「이 프로젝트의 서버인가」를 판정하는 방법

가장 어려운 판정이다. 후보를 검토했다:

| 후보 | 기각 사유 |
|------|----------|
| `ps` 로 프로세스 커맨드라인 확인 | `serve` 가 만드는 문서 루트는 `mktemp -d` 결과라 **프로젝트를 식별하지 못한다.** 식별시키려면 `serve` 의 기동 명령을 바꿔야 하고, 그러면 기존 `stop` 패턴과 `pkill` 패턴이 연쇄로 흔들린다 |
| 임시 디렉토리 이름을 프로젝트 경로에서 결정적으로 유도 | 위 문제는 풀리지만 `serve` 를 개조해야 하고, 해시 도구(`shasum`/`md5`) 의존이나 긴 경로 정규화가 붙는다 |
| **HTTP 로 받아 본 바이트가 우리 파일과 같은지 비교** | **채택.** `serve` 를 한 글자도 안 고친다. 심볼릭 링크 구조상 "우리 파일을 서빙 중" ⟺ "GET 결과가 우리 파일 바이트와 동일" 이 정확히 성립한다 |

**채택안의 정확성**: 서버는 심볼릭 링크를 통해 **같은 inode** 를 읽는다. 따라서 재사용 판정이
한 번 참이면 이후에도 계속 참이다(파일이 바뀌어도 링크는 같은 파일을 가리킨다). 판정 시점은
`init` 이 파일을 다 쓴 뒤이므로 제목·단계·타임스탬프가 모두 들어간 상태이며, 서로 다른
프로젝트의 대시보드가 그 시점에 바이트까지 동일할 확률은 무시할 수 있다.

**부수 효과 하나가 공짜로 따라온다**: 이전 부팅 때 뜬 서버가 살아 있지만 임시 디렉토리가 OS 에
청소돼 404 를 내는 상황도, 바이트 비교가 자동으로 "남의 것"으로 분류한다. 별도 처리가 필요 없다.

### 포트 후보와 상수

| 상수 | 값 | 근거 |
|------|-----|------|
| `DZ_AUTO_PORT_BASE` | `8791` | `serve` 의 기존 기본 포트와 **동일**. 두 경로가 같은 포트에서 만나야 재사용이 성립한다 |
| `DZ_AUTO_PORT_TRIES` | `3` (8791·8792·8793) | 동시에 대시보드를 띄운 프로젝트 3개까지 수용. 4개째부터는 `file://` 폴백 — 흔치 않고, 폴백이 치명적이지 않다. 스캔 1회에 후보 3개를 다 보므로 Bash 왕복은 **항상 1회**다 |

**우선순위 규칙: `REUSE` 가 `FREE` 보다 우선한다.** 8791 이 남의 서버이고 8792 가 우리 것이면
8792 를 재사용한다. 후보를 낮은 번호부터 훑되 `REUSE` 를 하나라도 찾으면 그것을 쓰고,
없을 때만 **가장 낮은 `FREE`** 를 쓴다. 이 규칙이 없으면 같은 프로젝트에 서버가 계속 쌓인다.

### 신설 절 — 「자동 발행」 (`serve` 절 **바로 앞**에 둔다)

배치 이유: `init` 절과 `serve` 절 **사이**에 두면 두 호출자 모두에게 물리적으로 가깝고,
`serve` 의 기동 명령을 참조하는 문장이 바로 다음 절을 가리키게 된다.

> 아래는 `commands/dashboard.md` 에 들어갈 **문서 원문**이다. 구현자는 이 문장을 그대로 옮긴다.

````markdown
## 자동 발행 — `init` 의 공통 하위 절차

> `init` 의 **두 분기 모두**(신규 생성 후 10단계 / 기존 파일 조기 종료)가 이 절차를 부른다.
> **`step`·`log`·`impl` 은 이 절차를 부르지 않는다** — 서버를 띄우지도, 브라우저를 열지도 않는다.
> 세션 중 수십 번 불리는 명령이 프로세스를 만들거나 창을 띄우면 안 된다.
>
> **이 절차의 어떤 실패도 `init` 을 중단시키지 않는다.** 대시보드 파일은 이미 만들어졌고
> 그것이 본체다. 서버·브라우저는 편의이며, 실패는 에러가 아니라 **한 티어 낮은 안내**로 처리한다.

### 발행 티어 — 위에서부터 시도하고, 안 되면 조용히 내려앉는다

| 티어 | URL | 조건 | 얻는 것 |
|------|-----|------|--------|
| 1 | `http://localhost:{포트}/dashboard.html` | 서버 재사용 또는 기동 성공 | 5초 폴링 자동 갱신 + 플로팅 버튼 활성 |
| 2 | `file://{절대경로}/.claude/dashboard.html` | 서버 불가(python3 없음 · 후보 포트 전부 점유 · 기동 실패) | 포커스 시 갱신 |

**브라우저 열기는 티어와 직교한다.** 티어 1·2 어느 쪽이든 확정된 URL 에 대해 아래 「브라우저 열기」를
시도하고, 그마저 불가능하면 URL 을 출력해 사용자가 직접 열게 한다. 즉 최악의 결과가 **현재 동작과
정확히 같다** — 이 기능은 어떤 환경에서도 기존 경험을 나쁘게 만들지 않는다.

### 1. 서버 가용성 확인

`python3 --version` 이 실패하면 **티어 2로 내려간다**(3번으로). 다른 서버를 설치하지 않는다.

### 2. 포트 스캔 — Bash 1회, 결과는 3형태 중 하나

후보 포트는 **8791 · 8792 · 8793** 이다(`serve` 의 기본 포트에서 시작해 3개).
아래를 그대로 실행한다. 셸이 변수 확장을 하지 않도록 `$` 를 쓰지 않는다.

```bash
python3 -c "
import socket, urllib.request, pathlib
mine = pathlib.Path('.claude/dashboard.html').read_bytes()
free = None
for port in (8791, 8792, 8793):
    if socket.socket().connect_ex(('127.0.0.1', port)) != 0:
        if free is None: free = port
        continue
    try:
        got = urllib.request.urlopen('http://127.0.0.1:%d/dashboard.html' % port, timeout=1).read()
    except Exception:
        continue
    if got == mine:
        print(port, 'REUSE'); raise SystemExit
print(free, 'FREE') if free else print('NONE')
"
```

출력은 반드시 아래 셋 중 하나다. **다른 해석을 만들지 않는다.**

| 출력 | 의미 | 다음 행동 |
|------|------|----------|
| `{포트} REUSE` | 그 포트에서 **이 프로젝트의 대시보드**가 이미 서빙 중이다 | 기동하지 않는다. 3번으로 (`started=false`) |
| `{포트} FREE` | 그 포트가 비어 있다 | 아래 2-a 로 기동한 뒤 3번으로 (`started=true`) |
| `NONE` | 후보 3개가 전부 **다른 프로젝트**의 서버다 | **티어 2로 내려간다.** 3번으로. 보고에 "포트 8791~8793 이 다른 대시보드에 쓰이고 있습니다. `/dashboard serve stop <포트>` 로 정리할 수 있습니다"를 덧붙인다 |

- **`REUSE` 가 `FREE` 보다 우선한다.** 위 명령이 이미 그 순서를 보장한다 — 재사용 대상을 찾으면
  즉시 끝내고, 못 찾았을 때만 가장 낮은 빈 포트를 낸다. **이 우선순위가 없으면 같은 프로젝트에
  서버가 계속 쌓인다.**
- 명령 자체가 실패하거나(파일 없음 등) 위 셋이 아닌 출력이 나오면 **추측하지 말고 티어 2로 내려간다.**

**2-a. 기동** — `serve` 절차 3단계의 명령을 **그대로** 쓴다(복제해 변형하지 않는다).
`{포트}` 만 스캔이 확정한 값으로 채운다.

    DZ_DIR=$(mktemp -d) && ln -s "$PWD/.claude/dashboard.html" "$DZ_DIR/dashboard.html" \
      && python3 -m http.server {포트} --bind 127.0.0.1 --directory "$DZ_DIR"

- Bash 도구의 **백그라운드** 옵션으로 실행한다.
- `--bind 127.0.0.1` 은 **생략 금지**다(`serve` 와 같은 이유 — 기본값은 모든 인터페이스다).
- 기동 직후 그 백그라운드 태스크의 출력을 **한 번** 확인한다. `Address already in use` 가 보이면
  스캔과 기동 사이에 다른 세션이 그 포트를 채간 것이다. **다른 포트를 추측하지 말고 티어 2로
  내려간다**(3번으로). 이 경합은 드물고, 폴백이 이미 준비돼 있다.
- **`nohup`·`setsid` 로 프로세스를 분리하지 않는다.** 세션에 매인 수명이 의도된 기본값이다.

### 3. URL 확정

- 티어 1: `http://localhost:{포트}/dashboard.html`
- 티어 2: `file://<현재 작업 디렉토리 절대경로>/.claude/dashboard.html`

> 스캔은 `127.0.0.1` 로 확인하고 안내는 `localhost` 로 한다. 스캔은 **바인딩한 그 주소**를 정확히
> 찔러야 하고, 사용자 대면 URL 은 `serve` 5단계가 이미 쓰던 표기와 같아야 하기 때문이다.
> 브라우저에서 `localhost` 가 안 열리면 `http://127.0.0.1:{포트}/dashboard.html` 을 안내한다.

### 4. 브라우저 열기 — 되면 하고, 안 되면 **조용히** 넘어간다

아래 순서로 **한 번씩만** 시도한다. **재시도하지 않고, 루프를 돌지 않고, 실패를 에러로 보고하지
않는다.** 성공하면 즉시 5번으로 간다.

1. **이 세션에 URL 을 여는 도구가 이미 있으면 그것을 쓴다.** 브라우저 pane, 브라우저 MCP 서버 등
   **지금 사용 가능한 도구 목록에 실제로 존재하는** 것만 해당한다. **없다고 새로 설치하거나
   설정하지 않는다.**
2. **없으면 OS 기본 열기 명령을 시도한다.** 아래를 모두 만족할 때만 실행한다.
   - `$SSH_CONNECTION` 이 설정돼 **있지 않다.** 설정돼 있으면 원격 세션이므로 **시도하지 않는다** —
     명령이 열어 봐야 사용자가 보는 화면이 아니고, 애초에 그 포트는 원격 머신 것이다.
   - `uname -s` 결과가 `Darwin` → `open "<URL>"`
   - `uname -s` 결과가 `Linux` **이고** `$DISPLAY` 또는 `$WAYLAND_DISPLAY` 중 하나가 설정돼 있다
     → `xdg-open "<URL>"`
   - 그 밖의 경우(판정 불가, 헤드리스, 컨테이너) → **시도하지 않는다.**
3. **둘 다 못 하면 아무것도 하지 않는다.** 5번의 보고에 URL 이 이미 들어 있으므로 사용자가 직접 연다.

> 명령이 실패했는지 성공했는지 **깊이 판정하지 않는다.** 종료 코드가 0 이 아니면 열지 못한 것으로
> 보고 그대로 5번으로 간다. 브라우저가 실제로 떴는지를 확인할 방법은 없고, 확인하려 들면
> 절차가 비결정적이 된다.

### 5. 보고 — 한 덩어리로 한 번만

| 상황 | 보고에 반드시 포함 |
````

## 설계 결정과 근거

### 1. 서버 재사용 판정을 **HTTP 바이트 비교**로 한다 (프로세스 조사 아님)

**문제**: "이 포트의 서버가 **이 프로젝트**의 대시보드를 서빙하는가"를 알아야 한다.
모르면 (a) 남의 프로젝트 서버를 재사용해 엉뚱한 화면을 띄우거나 (b) 재사용을 포기하고 매 세션
서버를 하나씩 쌓는다.

**채택**: `GET /dashboard.html` 의 응답 바이트가 `.claude/dashboard.html` 과 같으면 우리 것이다.

- `serve` 를 **한 글자도 안 고친다.** 프로세스 식별을 하려면 문서 루트 이름을 결정적으로 바꿔야
  하고, 그러면 `stop` 의 `pkill` 패턴까지 연쇄로 흔들린다.
- 심볼릭 링크 구조상 이 판정은 **한 번 참이면 계속 참**이다(같은 inode 를 읽는다).
- 임시 디렉토리가 청소돼 404 가 나는 좀비 서버도 자동으로 "남의 것"이 되어 걸러진다.
- 비용: 40KB 남짓 파일 하나를 루프백으로 읽는 것. 무시 가능하다.

**기각**: `ps`/`pgrep` 파싱 — `mktemp -d` 경로는 프로젝트를 식별하지 못하고, 식별시키려면 위 연쇄
변경이 필요하다. 해시 기반 디렉토리 이름 — `shasum`/`md5` 의존과 경로 정규화가 붙는데, 얻는 것은
바이트 비교와 같다.

### 2. 포트 스캔 **결과를 3개 토큰으로 압축**한다

`step` 절차가 "grep 1회 → 결과 3줄 → 결정적 분기"인 것과 같은 형태다. 메인 세션이 `ps` 출력이나
에러 문자열을 **해석**하게 두면 판정이 비결정적이 되고, 같은 상황에서 세션마다 다르게 행동한다.
Bash **1회 왕복**으로 후보 3개를 모두 훑고 `REUSE`/`FREE`/`NONE` 중 하나만 내는 이유다.

**`REUSE` > `FREE` 우선순위가 이 토큰 설계의 핵심**이다. 낮은 번호 우선으로만 짜면
"8791=남의 것, 8792=우리 것" 상황에서 8793 에 우리 서버를 또 띄운다.

### 3. `init` 의 **두 분기 모두** 자동 발행한다

기존 파일이 있어 조기 종료하는 분기도 발행한다. 근거: **세션이 시작됐다는 사실은 두 분기가
같다.** 세션 2 를 시작한 사용자에게 "파일이 이미 있으니 알아서 여세요"는 이번 요청의 정면 위반이다.
그리고 재사용 판정이 있으므로 이 분기가 서버를 중복 기동하는 일은 없다 — 대개 `REUSE` 로 끝난다.

한편 **`step`/`log`/`impl` 은 절대 발행하지 않는다.** 발행 지점을 `init` 하나로 못 박는 것이
"세션당 최대 1회"를 보장하는 유일한 장치다. 두 분기가 **같은 하위 절차 한 곳**을 참조하게 만든
것도 같은 이유다 — 절차가 복제되면 한쪽만 고쳐지는 날이 온다.

### 4. `file://` 안내를 **지우지 않고 폴백 티어로 강등**한다

완전 대체는 위험하다. python3 이 없거나, 포트가 다 막혔거나, 백그라운드 실행이 막힌 환경에서
`init` 이 **아무 URL 도 못 주는** 상태가 되면 기능이 순수한 퇴행이 된다. 티어 2 를 남겨 두면
최악의 결과가 **현재 동작과 정확히 같다.** T22-69 가 이 문자열의 생존을 강제한다.

### 5. 티어 사다리와 브라우저 열기를 **직교시킨다**

`(서버 성공/실패) × (브라우저 열기 가능/불가)` 를 4가지 케이스로 나열하지 않고, **URL 확정 →
그 URL 열기 시도**의 2단계로 분리했다. 조합 폭발이 사라지고, "브라우저를 못 열어도 서버는 떠
있다" 같은 부분 성공이 자연스럽게 표현된다. 절차 문서에서 케이스 나열은 곧 LLM 의 오해석
지점이므로, 나열을 줄이는 것 자체가 품질이다.

### 6. 브라우저 열기 사다리에서 **OS 명령이 주축**이고 도구는 대안이다

조사 결과 "순수 터미널 세션에는 브라우저를 열 수단이 없다"는 전제가 틀렸다 — Bash 가 있으면
`open`/`xdg-open` 이 있다. 그래서 사다리는 다음 순서다:

1. 세션에 **이미 있는** URL 열기 도구 (있으면 가장 매끄럽다 — 에이전트가 화면을 직접 볼 수도 있다)
2. OS 열기 명령 (이식성의 주축)
3. 포기 (URL 출력)

**"없으면 설치·설정하지 않는다"** 를 명시하는 이유: 없는 MCP 서버를 붙이려 드는 순간 `init` 이
몇 분짜리 작업이 된다.

`$SSH_CONNECTION` 가드는 **정확성 문제**다. macOS 에서 SSH 로 붙어 `open` 을 실행하면 원격 머신의
콘솔에서 열린다 — 사용자는 아무것도 못 보고, 원격 머신에는 엉뚱한 창이 뜬다. 게다가 포트 자체가
원격 것이라 URL 도 사용자 브라우저에서 무의미하다. 시도조차 하지 않는 것이 맞다.

### 7. 실패를 **에러로 보고하지 않는다**

`serve` 는 opt-in 이라 실패 시 "중단하고 보고"가 옳았다(사용자가 그것만을 요청했으므로).
자동 경로는 다르다 — 사용자는 **대시보드 기록**을 요청했고 발행은 부수 효과다. 여기서 에러를
띄우면 전체 경로 작업의 착수 보고가 매번 경고로 시작한다. 그래서 자동 경로의 실패는 전부
**한 티어 낮은 안내**로 흡수하고, `init` 은 계속 성공한다.

### 8. 새 하위 명령·새 인자·새 셀렉터를 **하나도 만들지 않는다**

`/dashboard open` 을 만들면 규약이 늘고 `argument-hint` 가 또 길어진다. 자동 발행은 `init` 의
마지막 단계일 뿐 독립 개념이 아니다. 직전 라운드가 커밋 `56229a1`(인자를 붙였다가 기능째 제거)의
교훈을 명시적으로 계승한다.

### 9. 템플릿을 **한 줄도 건드리지 않는다**

스크립트는 이미 `location.protocol` 로 모드를 가른다. `http://` 로 열리면 폴링과 PiP 가 저절로
켜진다. 이번 기능이 스크립트에 요구하는 것은 **없다.** 이 성질 덕분에 T22-29~34, 38~41, 51~53,
64~67 같은 스크립트 관련 검증이 전부 무영향이고, 리스크의 대부분이 사라진다.
**구현자는 템플릿 코드 블록을 열 이유가 없다.**

### 10. 스코프 아웃과 사유

| 제안 | 사유 |
|------|------|
| 서버를 세션 종료 시 자동 종료 | 커맨드 문서에 그럴 권한이 없다. 대신 세션 수명에 매이도록 `nohup` 을 **안 쓰고**, 보고에 정리 명령을 매번 넣는다 |
| 포트를 파일에 기록 | 상태 파일 금지 원칙 위반. 스캔이 매번 정답을 준다 |
| 후보 포트 3개 초과 | 4개째 동시 프로젝트는 드물고 폴백이 치명적이지 않다. 늘리면 스캔 시간만 는다 |
| `serve` 의 명시 포트에도 스캔 적용 | 사용자가 지정한 포트를 몰래 옮기지 않는다 |

## 리스크와 대안

### 1. **매 전체 경로 작업마다 Bash 권한 프롬프트가 뜬다** — 최대 리스크

자동 발행은 최소 2회의 Bash 호출(스캔 + 기동)과 1회의 브라우저 열기 명령을 쓴다. 허용 목록이
없는 프로젝트에서는 **착수 보고가 권한 승인 3연타로 시작**한다. 대시보드는 "조용히 옆에서
기록되는 것"이 미덕인데, 이 마찰은 그 미덕을 정면으로 깎는다.

**완화**: 보고에 허용 목록 추가 방법을 한 줄 안내하고(예: `Bash(python3 -m http.server:*)`,
`Bash(open:*)`), 스캔을 Bash **1회**로 압축한 것도 이 마찰을 줄이려는 설계다(설계 결정 2).

**남는 위험**: 그래도 첫 회는 프롬프트가 뜬다. 승인 결정 5(off 스위치)와 연결된 문제다.

### 2. 브라우저 탭이 매 세션 중복으로 열린다

`init` 은 세션당 1회지만, 같은 프로젝트에서 세션이 3번 돌면 탭이 3개 열린다(브라우저는 같은 URL
이라도 새 탭을 연다). 기존 탭을 재사용하도록 강제할 방법은 없다.

**완화**: 빈도가 세션당 1회로 묶여 있다. **대안**(승인 결정 3): "새로 기동했을 때만 연다" 규칙으로
바꾸면 중복이 사라지지만, 사용자가 탭을 닫고 세션을 새로 시작한 경우 아무것도 안 열려 요청을
만족하지 못한다. 트레이드오프를 사용자가 고르는 편이 맞다.

### 3. 서버가 세션 종료 후에도 남는다 (수동 확인 11 에 달림)

Claude Code 가 백그라운드 태스크를 세션 종료 시 정리하는지가 확정적이지 않다. 정리한다면 이
리스크는 존재하지 않고, 정리하지 않으면 프로젝트마다 python 프로세스가 하나씩 남는다.

**완화 3중**: (a) 재사용 판정이 있어 **같은 프로젝트에서는 누적되지 않는다**, (b) 티어 1 보고가
매번 정리 명령을 포트 포함 형태로 안내한다, (c) `NONE` 폴백이 "포트가 다 찼습니다 — 정리하세요"를
사용자에게 알려 자연스러운 청소 시점을 만든다. **`nohup` 을 쓰지 않는 것**도 이 리스크를
키우지 않으려는 결정이다.

### 4. 스캔과 기동 사이의 경합 (TOCTOU)

두 세션이 동시에 `FREE 8791` 을 받고 둘 다 기동하면 하나는 `Address already in use` 로 죽는다.

**완화**: 진 쪽은 **추측 재시도 없이 티어 2로 내려간다.** 조용히 `file://` 로 뜨고 작업은 계속된다.
락을 도입하지 않는다 — 확률이 낮고 폴백이 이미 있는데 락을 넣으면 정리 책임이 새로 생긴다.

### 5. `localhost` 가 `::1` 로 먼저 해석돼 연결이 실패한다

서버는 `127.0.0.1` 에만 바인딩한다. 브라우저가 `localhost` → `::1` 로 붙으면 실패할 수 있다
(대부분의 브라우저는 IPv4 로 폴백한다).

**완화**: 티어 1 안내에 "안 열리면 `http://127.0.0.1:{포트}/dashboard.html`" 한 줄을 넣는다.
바인딩을 `::` 로 넓히지 **않는다** — T22-35 가 막는 노출 위험 쪽이 훨씬 크다.

### 6. 검토했으나 채택하지 않은 대안

| 대안 | 내용 | 기각 사유 |
|------|------|----------|
| **A. 서버 없이 `file://` 만 자동으로 연다** | 브라우저 열기만 자동화 | 요청의 절반("서버를 띄우고")을 버린다. 폴링·플로팅이라는 실질 보상이 사라진다. **다만 티어 2로 이미 설계 안에 흡수돼 있다** |

| 선택지 | 내용 |
|--------|------|
| **A (권장)** | **사다리**: ① 세션에 이미 있는 URL 열기 도구 → ② OS 명령(`open`/`xdg-open`, `$SSH_CONNECTION` 없고 Linux 는 `$DISPLAY` 있을 때만) → ③ 시도 안 함, URL 출력. **각 단계 1회만, 재시도 없음, 실패는 에러가 아님** |
| B | OS 명령만 쓴다 (도구 탐색 생략) — 더 단순하지만 브라우저 pane 환경에서 에이전트가 화면을 직접 볼 기회를 버린다 |

> 근거: "순수 터미널엔 수단이 없다"는 전제가 틀렸다. Bash 가 있으면 `open`/`xdg-open` 이 있고,
> 이것이 이식성의 주축이다.

### 결정 2 — 서버 자동 기동의 대가 (난제 2)

| 항목 | 판단 |
|------|------|
| (a) 포트 충돌 | **8791·8792·8793 을 Bash 1회로 스캔.** 결과는 `{포트} REUSE` / `{포트} FREE` / `NONE` 3형태뿐 |
| (b) 이미 떠 있으면 | **재사용한다.** 판정은 "GET 한 바이트 == 우리 파일 바이트". `REUSE` 가 `FREE` 보다 우선 |
| (c) 세션 후 잔존 | **자동 종료하지 않는다.** `nohup` 을 쓰지 않아 세션에 매이게 두고, 티어 1 보고에 **매번** `/dashboard serve stop {포트}` 를 안내한다. 재사용 덕에 같은 프로젝트에서는 누적되지 않는다 |
| `serve` 의 무추측 규칙 | **그대로 둔다.** 스캔은 자동 경로 전용 (대안: `serve` 도 스캔하게 통일 — 일관되지만 명시 포트를 몰래 옮기게 된다) |

### 결정 3 — 기존 `init` 가드와의 상호작용 (난제 3)

| 선택지 | 내용 |
|--------|------|
| **A (권장)** | **두 분기 모두 발행한다.** 조기 종료 분기도 세션 시작이므로 화면이 떠야 한다. 재사용 판정이 있어 서버는 중복되지 않고, `init` 은 세션당 1회라 탭도 최대 1개 는다 |
| B | 신규 생성(1번 "존재하지 않으면") 분기에서만 발행 — 탭 중복이 0 이지만, **세션 2 를 시작한 사용자는 여전히 URL 을 손으로 열어야 한다** |

> 어느 쪽이든 **`step`/`log`/`impl` 은 발행하지 않는다** — 이건 재논의 대상이 아니다.

### 결정 4 — 10단계(`file://` 출력)와의 관계 (난제 4)

| 선택지 | 내용 |
|--------|------|
| **A (권장)** | **폴백으로 유지.** 10단계를 자동 발행 호출로 바꾸되, `file://` 안내는 티어 2 로 절차 안에 살려 둔다. 최악의 결과가 현재 동작과 정확히 같아진다 |
| B | 완전 대체 — 문서가 짧아지지만 python3 없는 환경에서 `init` 이 **아무 URL 도 못 주는** 순수 퇴행이 된다 |

**부수 결정**: `serve` 5단계도 같은 「브라우저 열기」 하위 절차를 부르게 한다(1줄).
`init` 은 열어 주는데 `serve` 는 안 열어 주는 비일관을 없앤다. **거부하면 이 1줄만 빼면 된다.**

### 결정 5 — 자동 발행 off 스위치를 만들 것인가 (새로 드러난 문제)

이 변경은 **모든 전체 경로 작업의 기본 동작**을 바꾼다 — 백그라운드 프로세스가 뜨고 브라우저가
열리며 첫 회에는 Bash 권한 프롬프트가 뜬다(리스크 1).

| 선택지 | 내용 |
|--------|------|
| **A (권장)** | **새 설정 키를 만들지 않는다.** `/dashboard off`(`dashboard_enabled`) 라는 기존 탈출구가 이미 있고, 자동 경로는 실패에 관대하다. 불만이 실제로 나오면 그때 키를 판다 (YAGNI) |
| B | `.claude/settings.local.json` 에 `dashboard_autoserve`(기본 `true`) 추가 — 메인 세션이 `dashboard_enabled` 를 읽는 **바로 그 순간** 함께 읽으므로 파일 접근이 늘지 않는다. 대신 문서 3곳(CLAUDE.md·README·dashboard.md)과 T23 계열 검증이 늘고, 키가 둘이 되면 "꺼졌는데 왜 안 되지"의 경우의 수도 둘이 된다 |
