# 대시보드 UI 정리 — 세션 탭 제거 · `init` 항상 재발행 · 「지금」 카드 재설계 · 부제 제거 (PRP)

## 요구사항 요약

`/dashboard` 산출물(`.claude/dashboard.html`)에서 **쓰이지 않거나 중복되는 UI 를 걷어내고, `init`
한 번으로 브라우저에 곧바로 보이게** 한다. 구체적으로는 (1) 초기 발행 시 브라우저 탭이 열리는 데서
그치지 않고 **그 탭이 전면으로 올라오게** 하고, (2) **메인 세션 구분 UI(세션 탭·구분선·세션 번호)를
전부 제거**하고 `init` 이 불릴 때마다 대시보드를 **처음부터 새로** 만들며, (3) 단계 목록과 내용이
겹치던 **「지금」 카드를 목록에 없는 정보만 담도록 재설계**하고 내부 정렬을 바로잡고, (4) 정보량이
낮은 **`#dz-subtitle` 을 제거**한다.

이 저장소에서 `commands/dashboard.md` 는 **문서이자 곧 구현**이다 — 오케스트레이터가 따르는 절차와
산출물 HTML 템플릿 전문이 한 파일에 들어 있다. 따라서 이 PRP 의 구현은 그 파일(+ 회귀 테스트 + README)
편집이다.

### 착수 전에 반드시 알아야 할 두 가지 사전 발견

> **발견 1 — 이 파일에는 자동화 회귀 테스트가 있다.**
> 요청서에는 "자동화 테스트가 없다"고 적혀 있으나 사실이 아니다. `tests/run.sh` 의
> `test_dashboard_template_integrity()`(L998~L1890)가 **T22-1~T22-90** 하위 검증으로
> `commands/dashboard.md` 를 grep 정합성 검사한다. 이번 변경은 그중 **최소 13개를 직접 깨뜨린다**
> (세션 탭·부제·`init` 재사용 분기를 존재 검증하는 항목들). 테스트 수정은 **선택이 아니라
> 구현 범위의 일부**다. 상세 목록은 [테스트 계획](#테스트-계획)에 있다.
> 실행: `bash tests/run.sh` (프로젝트 루트).

> **발견 2 — Write 도구는 "세션에서 읽지 않은 기존 파일"을 덮어쓰지 못한다.**
> 요구 2의 권장안("`init` 은 항상 템플릿을 새로 Write 한다")은 이 제약에 그대로 걸린다.
> 그래서 새 `init` 1단계는 **Bash 로 파일을 먼저 지운 뒤** Write 한다
> (`mkdir -p .claude && rm -f .claude/dashboard.html`). 이 한 줄이 (a) 디렉토리 보장,
> (b) 도구 제약 회피, (c) 낡은 바이트 잔존 방지를 동시에 처리하며 **존재 여부 분기를 없앤다.**
> 이 줄을 빠뜨리면 두 번째 `init` 이 도구 오류로 실패한다 — 구현 중 가장 밟기 쉬운 함정이다.

## 요청 4건과 최종 결정

| # | 사용자 요청 | 최종 결정 | 승인 필요 |
|---|------------|----------|:---:|
| 1 | 초기 발행 시 브라우저 자동 열기 + **그 탭으로 포커스** | 열기 절차는 **이미 있다**. 빠진 것은 **세션 내장 브라우저 도구 경로의 탭 활성화**뿐 — 그 경로에 "탭 선택/포커스 계열 도구가 함께 있으면 navigate 직후 한 번 더 호출한다"를 추가한다. OS `open`/`xdg-open` 경로는 **기본이 이미 포커스**이므로 무변경, 대신 `open -g`(백그라운드) 금지 한 줄을 가드로 남긴다 | 아니오 |
| 2 | 세션 탭 UI 전면 제거 + 매 메인 세션마다 새로 발행 | **권장안 A**: `init` 은 파일 존재 여부와 무관하게 **항상 처음부터 새로 만든다**. 로그 보존 로직·grep 앵커 기반 부분 치환·세션 번호·세션 탭·구분선을 **전부 제거**한다 | **예** (아래 트레이드오프) |
| 3 | 「지금」 카드가 단계 목록과 중복·정렬 불량 | 카드에서 **단계 번호·이름을 없애고**, 목록에 없는 값 3개(`경과` / `마지막 기록` / `다음`)만 **라벨-값 고정폭 2열**로 정렬한다. 불변식 7(파생 뷰)과 CSS 자동 숨김은 유지 | 아니오 |
| 4 | `#dz-subtitle` 제거 | 셀렉터·마크업·CSS(`.sub`, `body.dz-pip .sub`)·`init` 5단계·폴링 동기화 호출·헤더 주석까지 **전부 제거**. 동적 셀렉터 **7 → 6**. 그룹 문법의 그룹명은 **버린다**(다른 곳으로 옮기지 않는다) | 아니오 |

### 요구 2의 트레이드오프 — 승인이 필요한 유일한 결정

**권장안 A — `init` 은 언제나 완전히 새로 시작한다.**

- 얻는 것: 절차가 한 분기로 줄어든다. 사라지는 자산이 크다 — 「이미 존재하면」 분기(a~e),
  세션 번호 확정·갱신, 세션 구분 항목 prepend, 「세션 탭 갱신」 하위 절 전체(38줄), 템플릿 세대
  확인, 구현 세부 작업 초기화, 그리고 그 분기 때문에 필요했던 **grep 앵커 기반 부분 치환**이
  통째로 없어진다(방금 우리가 쓴 파일이므로 `old_string` 이 템플릿 그대로다).
  `<style>` 에 세션 규칙을 주입하던 경로가 사라져 **모든 대시보드의 CSS 가 템플릿과 동일**해지고,
  그 덕에 폴링의 `sessionTabsChanged()` 전체 리로드 경로도 함께 소멸한다.
- **잃는 것(이것이 승인 대상이다)**: 같은 메인 세션에서 `init` 을 두 번 부르면 **이전 작업의
  작업 추적 로그가 사라진다.** 지금은 보존됐다.
- 완화: `init` 은 CLAUDE.md 트리거 표상 **전체 경로 착수 시 1회**만 부르는 명령이고,
  `.claude/dashboard.html` 은 git 미추적 임시 산출물이다. 보고에 "이전 내용은 남지 않습니다"를
  한 줄 넣어 사고를 예방한다.

**대안 B — 세션 구분 UI 만 제거하고 로그는 계속 누적 보존한다.**

「이미 존재하면」 분기를 남기되 a~d(세션 번호·구분선·탭)만 지우고 e(상태 갱신)와 "9단계 건너뛰기"는
유지하는 안이다. 로그가 사라지지 않는다는 것이 유일한 장점이며, 대가가 셋이다. (1) "메인 세션마다
**항상 새로 발행**"이라는 요청 문구를 문자 그대로 만족하지 못한다 — 화면이 이전 작업에서 이어진다.
(2) 재사용 분기의 복잡성(grep 앵커 10종, 템플릿 세대 확인, impl 목록 초기화, "여기서 종료")이
전부 남는다. (3) **세션 구분 수단이 사라진 채 로그만 섞인다** — 서로 다른 작업의 항목이 시간순으로
뒤엉키는데, 그걸 풀려고 만든 것이 바로 지금 제거하려는 세션 탭이다. 즉 대안 B 는 세션 탭이 원래
풀던 문제를 되살린다.

> 참고로 검토했다가 기각한 절충안(대안 C): 로그를 보존하되 무명 구분선(`<hr>`) 하나만 남긴다.
> "세션 구분 UI 를 모두 제거"라는 요청과 정면으로 충돌하고, 결국 세션 개념을 반쯤 남긴다.

**→ 권장: A.** 사용자가 B 를 고르면 이 PRP 의 요구 2 절만 교체하면 되고, 요구 1·3·4 는 영향이 없다.

## 인터페이스 — 호출 규약

**파라미터는 한 글자도 바뀌지 않는다.** 바뀌는 것은 `init` 의 **관측 가능한 동작**이다.

```
/dashboard init "<제목>" "<단계1|단계2|...>"
/dashboard init "<제목>" "<그룹A:단계1,단계2|그룹B:단계1,단계2>"
```

호출 규약 절과 「CLAUDE.md 트리거」 표 아래에 아래 취지의 한 줄을 **명시적으로 추가**한다.

> **`init` 은 기존 `.claude/dashboard.html` 을 보존하지 않는다.** 호출될 때마다 파일을 지우고
> 처음부터 새로 만든다 — 이전 작업의 진행 상태도, 작업 추적 로그도 남지 않는다.
> 전체 경로 착수 시 **1회만** 부른다.

`step`·`impl`·`log`·`serve`·`on`/`off` 의 규약과 동작은 무변경이다.

## 「지금」 카드 재설계 (초안)

### 왜 지금 카드가 중복으로 느껴지는가

현재 카드의 첫 줄은 `지금 3. 구현 · 42분 경과 · 마지막 기록 6분 전`, 둘째 줄은 `다음 → 4. 검수` 다.
이 중 **`3. 구현` 과 `4. 검수` 는 바로 위 `ol#dz-steps` 의 `<li>` 에 번호·이름·상태 칩과 함께 이미
있다.** 카드에만 있는 값은 `42분 경과` 와 `마지막 기록 6분 전` 둘뿐이며, 그 둘이 중복된 이름들
사이에 끼어 눈에 띄지 않는다.

정렬이 어긋나 보이는 원인도 마크업에 그대로 있다.

- `.now-line{display:flex;align-items:baseline}` 에 폰트 크기가 11px(라벨) · 16px(단계명) ·
  12px(경과)로 제각각인 요소가 섞여 있고, 경과만 `margin-left:auto` 로 오른쪽 끝에 밀려 있다.
- 둘째 줄 `#dz-now-next` 가 **`class="step-detail"` 을 재사용**해 `margin-left:38px` 을 상속받는다.
  38px 은 단계 목록의 번호 배지(26px)+간격(12px)에 맞춘 값이라 이 카드 안에서는 아무 의미가 없다 —
  첫 줄은 왼쪽 끝, 둘째 줄은 38px 들여쓰기가 되는 이유가 이것이다.

### 새 마크업 (템플릿 body 1258~1261 교체)

```html
  <div class="card" id="dz-now-card">
    <div class="now-title">지금</div>
    <div class="now-row"><span class="now-label">경과</span><span class="now-value" id="dz-now-elapsed"></span></div>
    <div class="now-row"><span class="now-label">마지막 기록</span><span class="now-value" id="dz-now-since"></span></div>
    <div class="now-row"><span class="now-label">다음</span><span class="now-value" id="dz-now-next"></span></div>
  </div>
```

- 카드 제목 `지금` 은 아래 두 카드(`구현 세부 작업`·`작업 추적`)와 **같은 형태**다 —
  기존 규칙 `.log-title,.impl-title` 에 `.now-title` 을 **덧붙이기만** 한다(새 규칙 0줄).
- 값에 접두어를 넣지 않는다: `42분 경과` → `42분`, `다음 → 4. 검수` → `4. 검수`.
  라벨이 이미 그 뜻을 말하므로 문자열이 짧아지고, 라벨 열의 폭이 값의 정렬을 결정한다.

### 새 CSS (템플릿 `<style>` 1189~1194 교체, 6줄 → 6줄)

```css
  .now-row{display:flex;align-items:baseline;gap:10px;padding:3px 0}
  .now-label{flex:none;width:78px;font-size:11px;font-weight:800;letter-spacing:.3px;color:var(--muted)}
  .now-value{font-size:13.5px;font-weight:700;color:var(--navy);overflow:hidden;text-overflow:ellipsis;white-space:nowrap}
  #dz-now-elapsed{color:var(--blue)}
  .now-row:has(.now-value:empty){display:none}
  .wrap:not(:has(#dz-steps li.active)) #dz-now-card{display:none}
```

그리고 1232 줄을 `.log-title,.impl-title,.now-title{…}` 로 확장한다.

**정렬이 실제로 고쳐지는 지점**

| 문제 | 해법 |
|------|------|
| 라벨·값의 폰트 크기가 제각각이라 baseline 이 들쭉날쭉 | 값은 **전부 13.5px** 로 통일하고, 라벨만 11px 캡션. 행마다 독립적으로 baseline 이 맞는다 |
| 둘째 줄만 38px 들여쓰기 | `.step-detail` 재사용을 끊고 `.now-value` 로 교체 |
| 값의 시작 x 좌표가 행마다 다름 | `.now-label{flex:none;width:78px}` — **고정폭 라벨 열**이 값의 왼쪽 정렬선을 만든다 |
| 경과가 오른쪽 끝에 홀로 떠 있음 | `margin-left:auto` 제거. 값은 전부 같은 열에서 시작한다 |
| 값이 길면 줄바꿈돼 행 높이가 흔들림 | `.now-value` 에 `nowrap`+말줄임(`overflow:hidden` 이 flex 자동 최소 크기를 0으로 만들어 실제로 축약된다) |

> `width:78px` 은 매직 넘버지만 **입력이 고정**이라 안전하다 — 라벨 3종(`경과`·`마지막 기록`·`다음`)은
> 템플릿 상수이지 사용자 데이터가 아니다. 가장 긴 `마지막 기록`(11px/800/자간 .3px)이 약 70px 이라
> 8px 여유를 둔 값이다. 라벨 문구를 바꿀 때만 이 값을 함께 본다.

### 새 스크립트 (템플릿 `<script>`)

변수 선언(1313~1315) 교체:

```js
  var nowElapsed = document.getElementById('dz-now-elapsed');
  var nowSince = document.getElementById('dz-now-since');
  var nowNext = document.getElementById('dz-now-next');
```

`elapsedLabel()`(1337~1348)을 **삭제**하고 `renderNowCard()`(1349~1358)를 아래로 교체한다.
`parseStamp()`·`formatDuration()`·`phaseLabel()` 은 **그대로 둔다**(`phaseLabel` 은 다음 단계 이름에
계속 쓰인다).

```js
  function renderNowCard(){
    // 매트릭스 세션이거나 진행중 단계가 없으면 그릴 것이 없다 — 카드는 CSS 가 숨긴다.
    var active = wrap.querySelector('#dz-steps li.active');
    if(!active) return;
    var now = Date.now();
    var startedAt = parseStamp(active.getAttribute('data-started-at'));
    var updatedAt = parseStamp(wrap.querySelector('#dz-updated').textContent);
    // formatDuration 은 손상·미래 타임스탬프(시계 되감김 등)에 빈 문자열을 반환한다. 값이 비면
    // .now-row:has(.now-value:empty) 가 그 행을 통째로 숨겨 라벨만 남는 상태가 생기지 않는다.
    nowElapsed.textContent = startedAt ? formatDuration(startedAt, now) : '';
    var since = updatedAt ? formatDuration(updatedAt, now) : '';
    nowSince.textContent = since ? since + ' 전' : '';
    nowNext.textContent = active.nextElementSibling ? phaseLabel(active.nextElementSibling) : '';
  }
```

- **`since` 를 한 번 변수에 받는 이유**: 빈 문자열에 `' 전'` 을 붙이면 `" 전"` 만 남아 `:empty` 가
  풀리고 라벨과 함께 의미 없는 행이 나타난다. 기존 `elapsedLabel()` 이 조각 단위로 막던 실패를
  같은 방식으로 유지한다.
- 호출 지점(`renderNowCard(); setInterval(renderNowCard, NOW_TICK_MS);` 와 `apply()` 말미)은
  **위치·순서 모두 무변경**이다 — `if(!isServed)` 조기 반환보다 **앞**, `resizePipToFit()` **직전**.
- `#dz-now-*` 접두어를 유지하므로 `dz-current` 계열 부활을 막는 역방향 테스트(T22-61)를 건드리지 않는다.

## 브라우저 열기 개정안 (자동 발행 4번)

### 진단 — 이미 있는 것과 진짜 빠진 것

| 경로 | 현재 | 판정 |
|------|------|------|
| ① 세션에 이미 있는 URL 열기 도구(브라우저 pane·MCP 등) | "그것을 쓴다"까지만 지시. **탭을 전면으로 올리라는 지시가 없다** | **여기가 빠진 부분** — navigate 만 하고 사용자가 보던 탭이 그대로인 경우가 생긴다 |
| ② OS 기본 열기(`open` / `xdg-open`) | 옵션 없이 URL 만 넘긴다 | **이미 포커스된다.** macOS `open` 은 대상 앱을 전면으로 올리는 것이 기본이고, `xdg-open` 도 데스크톱 환경의 기본 핸들러가 창을 띄운다 → **무변경** |
| ③ 포기(URL 출력) | — | 무변경 |
| 발행 시점 | 자동 발행은 `init` 에서만 불린다 | **"초기 발행 시"라는 요구를 이미 만족** |

### 개정 문안 (경로 1·2)

````markdown
1. **이 세션에 URL 을 여는 도구가 이미 있으면 그것을 쓴다.** 브라우저 pane, 브라우저 MCP 서버 등
   **지금 사용 가능한 도구 목록에 실제로 존재하는** 것만 해당한다. **없다고 새로 설치하거나
   설정하지 않는다.**
   - 그 도구가 탭 목록 조회·탭 선택(select/activate/focus 계열) 도구를 **함께 제공하면**,
     navigate 직후 방금 연 탭을 **전면으로 올리는 호출을 한 번만** 더 한다. navigate 만으로는
     탭이 백그라운드에 열려 사용자가 보던 화면이 그대로일 수 있다.
   - 그런 도구가 **없으면 navigate 로 끝낸다.** 없는 기능을 다른 수단으로 흉내 내지 않는다
     (「없으면 설치하지 않는다」와 같은 원칙이다).
   - 두 호출 모두 **한 번씩만** 하고, 실패는 무시하고 5번으로 간다.
2. **없으면 OS 기본 열기 명령을 시도한다.** … (조건 3개 무변경)
   - `open`/`xdg-open` 은 **기본이 곧 포커스**다. macOS 에서 `-g`(백그라운드) 옵션을 **붙이지
     않는다** — 붙이면 탭은 열리지만 창이 뒤에 남아 이번 요구가 무너진다.
````

`serve` 5단계는 이 절차를 그대로 호출하므로 **수동 경로도 같은 개선을 물려받는다**(추가 편집 없음).

## 설계 결정과 근거

### 1. 존재 분기를 없앤 것이 이번 변경의 **단순화 본체**다

세션 탭 제거는 UI 삭제로 보이지만, 실제로 가장 크게 줄어드는 것은 `init` 이다. 「이미 존재하면」
분기는 (a) 세션 번호 확정, (b) 태그 치환, (c) 구분선 prepend, (d) 탭·CSS 규칙 주입, (e) 옛 파일을
전제한 grep 앵커 10종 + 템플릿 세대 확인 + impl 목록 초기화로 이루어져 있었고, 그 **전부의 존재
이유가 "로그를 보존하면서 세션을 구분한다"** 하나였다. 구분을 없애면 보존의 값도 사라지고, 보존을
없애면 분기가 사라진다. 남는 절차는 "지우고 → 쓰고 → 채운다"뿐이다. 이것이 KISS/YAGNI 판단이다.

### 2. `rm -f` 후 Write — 도구 제약을 **정면으로** 다룬다

Write 도구는 세션에서 읽지 않은 기존 파일을 덮어쓰지 못한다. 대안 두 가지를 검토했다.
① 파일을 먼저 Read 한 뒤 Write — 로그가 쌓인 파일을 통째로 읽는 가변 비용이 생기고, `log` 절차가
"파일 전체를 Read하지 않는다"로 어렵게 없앤 비용을 `init` 이 되살린다. ② 임시 파일에 쓴 뒤 `mv` —
Bash 호출이 늘고 실패 경로가 둘이 된다. **`rm -f` 는 Bash 1회로 디렉토리 보장까지 겸하고, 낡은
바이트가 남지 않음을 보장**한다. 채택.

### 3. 「지금」 카드에서 단계 번호·이름을 **없앤다**(줄이지 않는다)

카드 바로 위에 활성 `<li>` 가 번호 배지·이름·`[진행중]` 칩·상세와 함께 있고, PiP 압축 뷰에서도
활성 단계는 배경색까지 입혀 강조된다. 즉 "지금 어느 단계인가"는 **어떤 화면에서도 이미 답이
나와 있다.** 이름을 반만 남기는 절충(예: 이름만, 번호 없이)은 중복을 반만 줄이면서 정렬 문제는
그대로 남긴다. `dashboard-current-next-card.md` 의 확정 사항 2("카드는 어디에도 없던 정보를 최소
하나 담아야 한다")를 만족시키는 값은 **경과 시간과 마지막 기록 이후 경과** 두 개이고, 이 둘이
카드의 전부가 되는 것이 그 확정 사항의 가장 순수한 형태다. `다음` 은 사용자가 명시적으로 유지를
요청해 한 행으로 남긴다.

### 4. 정렬은 **고정폭 라벨 열**로 푼다 — grid 를 쓰지 않는 이유

2열 grid(`grid-template-columns:max-content 1fr`)도 같은 정렬을 만들지만, **값이 빈 행을 통째로
숨기는 요구**와 충돌한다. grid 의 라벨·값은 형제라서 `:empty` 로 값만 숨기면 라벨이 홀로 남고,
행을 감싸면 `display:contents` + `:has()` 조합이 필요해 규칙이 늘어난다. 행마다 flex 를 쓰면
`.now-row:has(.now-value:empty){display:none}` **한 줄**로 끝난다. `:has()` 는 이미 템플릿에서
두 번 쓰이고 있어 새 의존성이 아니다.

### 5. 부제가 담던 정보는 **되살리지 않고 버린다**

`#dz-subtitle` 은 `단계 흐름 요약 · 작업 유형`(+그룹 문법일 때 그룹명)을 담았다. 단계 흐름은 바로
아래 단계 목록·매트릭스 헤더에 그대로 있고, 작업 유형은 사실상 상수다(`/dashboard` 는 전체 경로
전용이다). 그룹명은 그룹이 2개 이상이면 매트릭스 행 머리(`#dz-group-{g}`)에 나오고, 1개일 때만
표시처가 없어진다 — 그 한 경우를 위해 제거 대상인 요소를 살려 두거나 제목에 끼워 넣는 것은
"제거해 달라"는 요청과 충돌한다. **버린다.**

### 6. 폴링의 **전체 리로드 경로가 함께 사라진다**

`sessionTabsChanged()` 는 "세션마다 `<style>` 에 CSS 규칙이 추가되고 라디오가 늘어난다"는 전제
위에 있었다. 세션 규칙 주입이 없어지면 **모든 대시보드의 `<style>`·라디오 집합이 템플릿과
동일**해져 전제가 사라진다. 함께 지워지는 것은 `reloadPending` 플래그와 `pagehide` 의 조건 분기,
그리고 "플로팅 중이면 PiP 창을 강제로 닫고 리로드"라는 가장 파괴적인 경로다. 폴링은 부분 치환만
남아 더 조용해진다.

### 7. 브라우저 경로는 **한 줄만** 늘린다

"열리기는 하는데 포커스가 안 된다"는 문제를 위해 별도 하위 명령이나 재시도 루프를 만들지 않는다.
자동 발행 절의 확립된 원칙(한 번씩만 시도 · 실패는 무시 · 없는 수단은 만들지 않는다)을 그대로
따르며, 조건부 한 문장을 얹을 뿐이다. `open -g` 금지는 **역방향 가드**다 — 나중에 "조용히 열자"는
선의의 수정이 이번 요구를 되돌리는 것을 막는다.

### 8. 불변식 번호를 유지한다

세션 탭 전용 불변식이 애초에 없었으므로 재번호할 근거가 없다. 문서 내 상호 참조와 테스트 주석이
번호로 서로를 가리키고 있어, 근거 없는 재번호는 순수 비용이다.
