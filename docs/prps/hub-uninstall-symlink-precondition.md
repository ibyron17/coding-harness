## 0. 요구사항 요약

M1 검수 2회차(N4)가 넣은 제거 사전조건 `check_uninstall_preconditions` 는 `~/.claude/rules`·`~/.claude/rules/hub`·
배포 규칙 파일 중 하나라도 심볼릭 링크면 무조건 거부한다. 그래서 (1) 지울 규칙이 없어도 거부해, dotfiles 로
`~/.claude/rules` 를 링크한 머신에서는 규칙 채널 이전의 옛 허브가 영구히 제거되지 않고(기준 `9f23534` 대비 회귀),
(2) 안내 「링크 대상 안의 규칙 파일을 직접 지운 뒤 다시 실행하십시오」를 따라도 링크가 그대로라 또 거부되며, 파일
링크일 때는 사용자 자신의 dotfile 을 지우라고 읽힌다(N7). (3) `remove_managed_rule_files` 의 「링크면 건너뛰고 경고」
분기는 사전조건 뒤라 도달할 수 없는데, 사전조건을 거치지 않는 호출이 생기면 N4 의 최악 상태(`bin/` 은 지워지고 규칙은
링크 너머에 남아 계속 로드)를 되살린다(N8). 이 설계는 거부를 **지울 배포 규칙이 링크 자신이거나 링크 너머에 실제로
있을 때**로 좁히고, 안내를 경우별로 나눠 **「안내대로 한 뒤 다시 실행하면 통과」**를 계약으로 삼고, 링크 분기를
**재판정 방어선**으로 바꾼다. 어느 경로도 링크를 지나 `rm`·`rmdir` 하지 않는다.

## 1. 실측 — 현재 동작 (2026-09-24)

방법: 스크래치패드에 경우마다 가짜 홈을 새로 만들고 명령마다 `HOME=` 을 명시해 현재 `hub/install.sh` 를 돌렸다(실제
`$HOME` 무접촉, `PYTHONDONTWRITEBYTECODE=1`). 옛 허브는 `git archive 9f23534 hub/bin`(26파일)을 샌드박스 `bin/` 에
풀어 재현했다. 경우 기호는 §5 와 같다.

- **거부 7경우(C1a·C1b·C2a·C2b·C3a·C3b·C3c)**: dry-run·실제·`--force` 모두 exit 1, 문구는 「심볼릭 링크입니다: …」 +
  위 안내. **안내대로 한 뒤 재실행도 7경우 전부 exit 1** — C1a 는 사용자 원본을 지운 뒤에도 끊긴 링크로 거부, C3c 는
  지울 것이 애초에 없어 영구 거부(N7 재현). **통과 3경우(C0·C4a·C4b)**: 세 모드 exit 0.
- 판정이 기댈 원시 동작(bash 3.2.57·BSD 도구):
  (a) 디렉터리·부모 링크 너머의 파일 링크도 `[[ -L ]]` 가 참이다(중간 링크는 해석되고 마지막 구성요소만 lstat).
  (b) 끊긴 디렉터리 링크는 `-d` 거짓, 그 안 경로의 `-L`·`-e` 도 거짓.
  (c) 디렉터리 링크 자신에 대한 `rmdir` 은 `Not a directory` 로 실패한다(원래 무해).
  (d) **부모 링크 아래 실제 빈 디렉터리의 `rmdir` 은 성공해 링크 대상(사용자 트리)을 바꾼다** — 막아야 할 실재 경로.
  (e) 파일 링크에 `rm -f` 는 링크만 지우고 원본을 남긴다. (f) 부모 링크를 지나는 `rm -f` 는 너머의 파일을 지운다.
  (g) `else` 없는 `if/elif` 가 어느 분기도 타지 않으면 0 이다 — `x=$(f)` 가 `set -e` 아래서 안전.
- `bash tests/run.sh --only T40` 실측 3초(§7.4 비용 추정의 바탕).

## 4. 결정

### UL1 — 거부는 「배포 자리가 링크」 또는 「규칙 디렉터리가 링크 너머이고 그 자리에 파일이 실제로 있음」일 때만
배포 규칙 이름마다(지금 1개) 순서대로 본다. ① 자리가 `-L` → **거부 A**. ② `find_rules_dir_symlink` 출력이 비지 않고
자리가 `-e` → **거부 B**. ③ 그 밖 → **통과**. 근거: 막아야 할 것은 「배포 자리에서 규칙이 계속 읽히는데 `bin/` 은 없음」과
「링크를 지나 사용자 트리를 바꿈」 둘뿐이다. 자리에 아무것도 없으면(`-e`·`-L` 모두 거짓) 링크가 있어도 남을 규칙도
지울 것도 없다 — 거부할 근거가 없다(C2b·C3b·C3c 통과, N7 회귀 해소). 끊긴 파일 링크(C1b)도 거부 A 다 — 읽힐 내용은
없지만 링크는 사용자가 만든 것이라 소유권 원칙상 우리가 지우지 않는다(안내 1회로 풀린다). 검사 깊이는 설치 쪽과 같은
두 단(`TARGET_RULES_DIR`·그 부모) + 파일이다. 조상 전체를 `cd`+`pwd -P` 로 보는 `is_symlinked_path` 는 쓰지 않는다 —
`/private` 밖의 조상(`HOME` 등)이 링크인 머신에서 오탐하고, 없는 경로를 「링크 아님」으로 읽는다(M3 가 닫은 구멍).
(검수 1회차 P4 정정: 처음 적은 「mktemp 샌드박스(`/var`→`/private/var`)에서 오탐」은 틀렸다 — `is_symlinked_path` 가
`/private` 접두를 떼고 비교해 그 경우는 링크 아님으로 판정한다, 실측.)

### UL2 — 안내는 경우별, 계약은 「안내대로 한 뒤 재실행 = 통과」
거부 A 는 「링크만 지우라, 원본은 건드리지 말라」, 거부 B 는 「링크 너머의 그 파일만 지우라, 링크는 지우지 말라」(부모
링크를 지우면 사용자의 규칙 연결 전체가 끊긴다). 경로는 링크를 거친 경로 그대로 쓴다. 안내를 한 번 따르면 입력이 ③ 으로
바뀌므로 재실행은 반드시 통과한다(§5 마지막 열). 거꾸로 A 에서 원본을 지워도(옛 안내대로) 끊긴 링크가 남아 같은 A 안내가
다시 나오므로 스스로 교정된다.

### UL3 — 링크 너머에서는 `rm`·`rmdir` 을 하지 않는다(빈 `hub/` 도 남긴다)
통과 경우라도 규칙 디렉터리가 링크 너머면 `remove_managed_rule_files` 는 아무것도 지우지 않고 `[INFO]` 한 줄로 끝낸다.
근거: 링크 너머는 사용자 트리(dotfiles — 버전 관리·여러 머신 공유 가능)다. `rmdir` 은 빈 디렉터리만 지우지만, 「링크를
지나 바꾸지 않는다」를 예외 없이 두어야 한 문장으로 검증된다(T40-12c). 빈 디렉터리는 규칙을 읽히지 않으므로 잔존 해가
없다. §1-(d) 가 이 경로의 실재를, (c) 가 디렉터리 링크 자신은 원래 안전함을 보였다.

### UL4 — N8: 링크 분기 = 재판정 방어선(거부면 1, 통과면 `[INFO]` 후 0)
N7 로 이 분기가 정상 흐름에서 도달된다(C2b·C3b·C3c). 그래서 N8 문자 그대로의 「무조건 `return 1`」은 서버 정지·훅 제거가
끝난 뒤 제거를 실패시키고(요구 1), 현행 「무조건 건너뛰고 0」은 사전조건을 거치지 않은 호출에서 N4 의 최악 상태를
되살린다. 분기는 `check_uninstall_preconditions` 를 **그대로 다시 부른다**. 정상 흐름에서는 이미 통과한 판정이라 같은
결과(`[INFO]` 후 0)이고, 사전조건을 거치지 않았거나 그 사이 링크 너머에 규칙이 생겼으면 거부 B 문구와 함께 1 을 돌려
`perform_uninstall` 이 `bin/` 삭제 전에 멈춘다. 판정을 한 벌만 두어 두 곳이 따로 표류하지 않는다(대가는 §9 R1). 분기를
함수 맨 앞(현행 「디렉터리 아님 → 0」보다 앞)에 두어, 규칙 디렉터리가 없는 C3c·끊긴 링크에서도 실제 출력이 dry-run
계획(UL5)과 같아지게 한다. 링크 밖 분기에는 방어선을 두지 않는다 — 거기서는 `rm -f` 가 파일 링크 자신만 지워 규칙이 더는
읽히지 않으므로 최악 상태가 아니고, 넓히면 T40-11 원장 행(사전조건 제거 변조 → exit 0)이 물 곳을 잃는다.

### UL5 — dry-run 계획 줄을 실제 동작과 맞춘다
링크 너머 통과 경우 계획은 「규칙 파일 제거 건너뜀」이다 — 현행 「배포한 이름만 rm -f, 비면 rmdir」은 UL3 뒤에 거짓이 된다.
사전조건이 첫 줄에서 이미 통과했으므로 「지울 파일 없음」 단정이 성립한다.

### UL6 — `--force` 우회 없음 유지, 설치 쪽 무변경
거부 A/B 를 강행하면 곧 링크 관통이나 최악 상태다(우회 = 결함). 좁힌 뒤 남는 거부는 전부 안내 1회로 풀리므로 우회 수요도
없다. `check_uninstall_preconditions` 가 `check_no_symlink_rule_targets` 를 더 부르지 않을 뿐 그 함수와 `check_preconditions`
는 그대로라 설치 동작은 구성상 불변이다(T40-10·T25-174·T25-175 가 계속 문다).

### 불변식 (요지)
- **최악 잔존 상태 불가** — `perform_uninstall` 이 `bin/` 삭제에 닿으려면 `remove_managed_rule_files` 가 0 이어야 하고, 0 인
  세 경로 모두에서 배포 자리는 비어 있다: 링크 너머 분기(재판정 통과 = 모든 자리가 `-L` 도 `-e` 도 아님) · 디렉터리 아님
  (그 아래 경로는 존재도 링크도 불가) · 평소 분기(`rm -f` 성공 = 자리 비움).
- **사전조건이 먼저** — `perform_uninstall`·`log_uninstall_plan` 첫 줄 `check_uninstall_preconditions || return 1` 그대로.
- **링크 관통 0** — `rm -f`·`rmdir` 은 규칙 디렉터리와 부모가 둘 다 링크가 아닐 때(평소 분기)만 돈다.

| 부모 링크 + 너머 자리가 파일 링크 | 1 | 거부 A(① 이 먼저) | 1 | 무변경 | 링크 삭제 → 0 |
| `~/.claude` 자신이 링크 | 0 | 변화 없음(비목표) | 0 | 현행 그대로(그 링크를 지나 삭제) | — |

공통: dry-run 은 어느 경우든 무변경이고, 사전조건이 첫 줄이라 종료 코드·거부 문구가 실제와 같다. `--force` 는 사전조건
판정에 관여하지 않아(UL6) force 열이 실제 열과 같다 — 하위 명령 실패 게이트만 우회한다(현행). 거부면 서버·훅·statusLine·
링크·링크 대상·`bin/` 전부 무변경. 통과면 `hub.py` 가 있을 때 서버 정지 → 훅 제거 → statusLine 제거가 현행대로 돈다.

## 6. 판정 모델·인터페이스

### 6.1 판정 모델(데이터 모델 대용 — bash 라 타입 대신 입력과 결과를 고정한다)
입력(배포 이름 `N` 마다): `-L "$TARGET_RULES_DIR/N"` · `-e "$TARGET_RULES_DIR/N"` · `rules_dir_link`(`find_rules_dir_symlink`
출력, 빈 값 = 링크 없음). 결과 4종: **거부 A**(자리가 링크) · **거부 B**(링크 너머에 파일) · **통과-평소**(`rules_dir_link`
빈 값) · **통과-링크 너머**(비지 않음, 지울 것 없음). 사전조건이 앞의 둘을, `remove_managed_rule_files`·`log_uninstall_plan`
이 뒤의 둘을 가른다.

### 6.2 시그니처
```
find_rules_dir_symlink()          # 인자 없음(전역 TARGET_RULES_DIR). stdout: TARGET_RULES_DIR 가 -L 이면 그 경로, 아니고
                                  #   부모가 -L 이면 부모 경로, 둘 다 아니면 빈 출력. 반환 항상 0. 부작용 없음.
check_uninstall_preconditions()   # 시그니처 불변. 0 통과 | 1 거부(stderr [ERROR] 2~3줄). 부작용 없음. 판정은 §6.1 ①②③.
remove_managed_rule_files()       # 시그니처 불변. 0 지움·지울 것 없음 | 1 rm 실패·방어선 거부.
                                  #   순서: 링크 너머 → 재판정(실패 1 / 통과 [INFO] 후 0, rm·rmdir 없음) → 디렉터리 아님 → 0 → 현행 rm·rmdir
log_uninstall_plan()              # 시그니처·반환 불변. 규칙 계획 줄만 rules_dir_link 유무로 분기.
```
호출부는 `local rules_dir_link` 와 `rules_dir_link=$(find_rules_dir_symlink)` 를 두 줄로 쓴다(선언·대입 분리 — 파일 관례).

### 6.3 출력 문구 원문 (`{…}` 는 변수 값)
| 경우 | 함수 | 원문 |
|---|---|---|
| 거부 A | `log_error` ×2 | `심볼릭 링크입니다: {TARGET_RULES_DIR}/{N}` · `링크만 지운 뒤 다시 실행하십시오 — 링크가 가리키는 원본 파일은 건드리지 마십시오` |
| 거부 B | `log_error` ×3 | `심볼릭 링크입니다: {rules_dir_link}` · `링크 너머에 허브 규칙 파일이 남아 있습니다: {TARGET_RULES_DIR}/{N}` · `그 파일만 지운 뒤 다시 실행하십시오 — 링크는 지우지 마십시오` |
| 통과-링크 너머(실제) | `log_info` | `규칙 파일 제거를 건너뜁니다 — {rules_dir_link} 가 심볼릭 링크이고 그 너머에 지울 허브 규칙 파일이 없습니다(링크는 건드리지 않습니다)` |
| 통과-링크 너머(dry-run) | `log_plan` | `규칙 파일 제거 건너뜀 — {rules_dir_link} 가 심볼릭 링크이고 그 너머에 지울 허브 규칙 파일이 없음(링크는 건드리지 않음)` |
| 방어선 | 재판정 | 거부 B 3줄 + 현행 `perform_uninstall` 의 `규칙 파일 제거 실패: {TARGET_RULES_DIR}` |
| 통과-평소 | — | 현행 그대로 |

옛 문구 `링크 대상 안의 규칙 파일을 직접 지운 뒤 다시 실행하십시오`(2곳)와 `… 가 심볼릭 링크라 제거를 건너뜁니다 — 링크
대상은 건드리지 않습니다` 는 사라진다. 거부 문구에 「아무것도 바꾸지 않았다」 류의 상태 단정을 넣지 않는다 — 방어선
경로에서는 서버 정지·훅 제거가 이미 끝난 뒤라 거짓이 된다.

### 6.4 앵커 줄 (원장 변조가 겨누는 줄 — 앞 공백까지 문면 그대로 둔다)
| 줄 | 위치 | 겨누는 원장 행 |
|---|---|---|
| `    if [[ -n "$rules_dir_link" && -e "$target_file" ]]; then` | 사전조건 루프(② 판정) | T40-12a·12b(신설) |
| `  if [[ -n "$rules_dir_link" ]]; then` | `remove_managed_rule_files` **에만** — `log_uninstall_plan` 은 `-z` 형태(평소 계획 먼저)로 써서 겹치지 않게 | T40-12c(신설) |
| `    check_uninstall_preconditions \|\| return 1` | `remove_managed_rule_files` 링크 분기(4칸) | T40-12d(신설) |
| `  check_uninstall_preconditions \|\| return 1` | `perform_uninstall`·`log_uninstall_plan` 첫 줄(2칸) | T40-11(기존) |
| `    rm -f "$TARGET_RULES_DIR/$(basename "$source_file")" \|\| return 1` | 평소 분기 | T40-2(기존) |

표 안의 `\|` 는 마크다운 이스케이프다(실제 문면·원장 값은 `||`). 신설 sed 4개는 BSD sed 로 확인했다 — 현재 파일의 어떤 줄에도 걸리지 않고, 위 형태의 표본 줄에는 각각 정확히 한 줄씩
걸린다. T40-11 의 `^  check…` 앵커는 4칸 방어선 줄에 걸리지 않는다(세 번째 글자가 공백). 앵커 줄이 바뀌면 T37-15 가
「sed 적용 후 바이트 변화 없음」으로 잡는다.

  필요조건 서술이라 링크 너머에서 손대지 않는 동작과 모순되지 않고, 「진행 기록」의 「설치·제거할 때 그 규칙 파일도 함께
  생기고 사라진다」는 §4 불변식(제거 완료 = 배포 자리 비움)이 보장한다. 링크 거부는 README 가 현행에도 서술하지 않는다.
  일괄 정리 때 쓸 수 있는 선택 문장: 「`~/.claude/rules` 등이 심볼릭 링크면, 그 너머에 허브 규칙 파일이 남아 있을 때만
  제거를 멈추고 무엇을 지우면 되는지 알려 준다.」
- `hub/install.sh` `usage` — 무변경(제거 순서 서술은 그대로 참).
- `tests/run.sh` T40 머리 주석 「하위 검증 T40-1~T40-11(M2 에서 T40-12~14 …)」 → 「T40-1~T40-12(M2 에서 T40-13~15 … 3회차
  N7·N8 이 T40-12a~d 를 써서 한 번 더 밀렸다)」, `test_desc` 의 `(T40-1~T40-11)` → `(T40-1~T40-12)`.

| R6 | 원장 sed 가 앵커 줄 문면에 묶인다 | §6.4 표. 어긋나면 T37-15 가 「바이트 변화 없음」으로 잡는다 |

검토했으나 채택하지 않은 대안:
- **링크 너머 파일을 설치기가 대신 지운다** — 사용자 dotfiles(버전 관리·여러 머신 공유)를 바꾼다. 요구 3 위반이고 다른 머신의 규칙까지 사라질 수 있다.
- **안내 문구만 고치고 판정은 M1 그대로** — C3c(옛 허브 + dotfiles 링크)가 영구 거부로 남는다. N7 의 핵심이 그대로다.
- **N8 문자 그대로(링크 분기 무조건 `return 1`)** — C2b·C3b·C3c 에서 서버 정지·훅 제거 뒤 실패한다(요구 1).
- **파일 링크는 링크만 자동으로 지운다(원본은 안전)** — 링크는 사용자가 만든 자산이라 소유권 원칙 밖이고 T40-11 의 거부 계약을 바꾼다. 안내 1줄로 풀린다.
- **방어선 가드를 정적 검사(본문에 호출 줄 존재)로** — 문면만 본다. T40 머리 주석이 스스로 적은 「조건부로만 깨지는 경로」 한계 그대로라, 스텁으로 분기를 실제로 태운다.

## 10. 사용자 승인이 필요한 결정

1. **폴더 연결(심볼릭 링크)이 있어도 지울 허브 규칙 파일이 없으면 제거를 끝까지 진행한다.** 설정 폴더를 다른 곳(dotfiles
   등)에 연결해 둔 컴퓨터에서 지금은 무엇을 해도 제거가 막힌다. 승인하면: 그 안에 허브 규칙 파일이 없는 경우(특히 규칙 기능이
   생기기 전의 옛 허브)는 다시 한 번에 제거된다.
2. **연결된 곳의 파일은 설치기가 대신 지우지 않고, 무엇을 지우면 되는지 경우별로 정확히 알려 주고 멈춘다.** 규칙 파일 자리가
   연결이면 「연결만 지우라(가리키는 원본은 지우지 말라)」, 폴더가 연결이면 「연결 너머의 그 파일만 지우라(연결은 지우지 말라)」.
   승인하면: 안내대로 한 번 지우고 다시 실행하면 제거가 끝나고, 설치기가 사용자의 dotfiles 안 파일을 직접 지우는 일은 없다.
3. **연결 너머에 남는 빈 hub 폴더는 지우지 않는다.** 승인하면: 제거 뒤 dotfiles 쪽에 빈 폴더 하나가 남을 수 있다. 아무 규칙도
   읽히지 않아 영향은 없고, 원하면 직접 지운다.
4. **강행 옵션(`--force`)으로도 이 멈춤은 건너뛸 수 없다(지금과 같음).** 승인하면: 강행해도 「실행 프로그램은 지워졌는데
   규칙은 남아 계속 읽히는」 반쪽 제거는 생기지 않는다.
