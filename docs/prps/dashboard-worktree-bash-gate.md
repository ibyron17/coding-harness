# `/dashboard` — 워크트리 격리 세션의 Bash 관문 통과

> 설계 문서(PRP). 구현 코드는 이 문서에 포함하지 않는다.
> **설계 기준 브랜치는 `main`** 이다 — 이 브랜치(`feature/hub-workflow-visibility`)의
> `commands/dashboard.md` 에는 `main` 의 「대시보드 경로 규칙」이 아직 없다(실측: 이 브랜치
> 사본에 `대시보드 경로 규칙`·`CLAUDE_CODE_SESSION_ID` 문자열이 0건, 1,344줄 / `main` 1,405줄).
> 이 브랜치 사본에 맞춰 고치면 병합 시 충돌하고 방금 도입된 세션별 경로 기능을 되돌린다.

---

## 1. 요구사항 요약

워크트리로 격리된 세션에서 `/dashboard` 스킬이 **착수 자체를 못 한다.** 격리 세션의 Bash 관문이
셸 `for` 루프·`$HOME` 이 아닌 환경변수 읽기·큰 heredoc·일부 `$(...)` 형태를 "워크트리를 벗어나지
않음을 검증할 수 없다"는 이유로 거부하기 때문이다. `main` 에서 도입된 「대시보드 경로 규칙」
(`CLAUDE_CODE_SESSION_ID` 를 읽어 세션별 대시보드 파일을 고르는 한 줄)은 **대시보드 파일에
접근하는 모든 Bash 블록의 첫 줄**이라, 이 규칙 이후로는 `init` 뿐 아니라 `step`·`log`·`impl`
까지 전부 첫 줄에서 막힌다.

이 작업의 목표는 **워크트리 격리 세션에서도 `/dashboard` 의 전 하위 명령이 동작하게 하는 것**
하나다. 대시보드의 DOM 계약·발행 티어·보고 형식·불변식은 바꾸지 않는다.

**결론 3가지**

1. **관문의 판정 경계는 단순한 구문 규칙이 아니다.** `$(pwd)`·`$(find …)` 가 `echo` 안에서는
   통과하고(M5·M6) `if [ -n … ]` 안에서는 거부된다(M4). heredoc 도 크기에 따라 갈린다(M9 대 M10).
   따라서 **"이 구문은 항상 거부된다"는 형태의 단정을 이 설계는 하지 않는다.** 아래 §8.3 의 정적
   가드도 이 사실을 전제로 한계를 명시한다.
2. **확실히 거부되는 것**(반복 재현): `$HOME` 이 아닌 환경변수 읽기(M1·M3), 셸 `for` 루프(M2),
   큰 heredoc(M10·M11).
3. **스크립트 파일 우회는 완전하다**(M12~M14). 파일 **내용은 검사되지 않으며**, 인자를 홑따옴표로
   감싸 넘기면 셸 확장 없이 문자 그대로 전달된다.

## 4. 파일 구조와 모듈 경계

```
commands/
├── dashboard.md              # 절차·계약·근거 (사람과 모델이 읽는다)
├── dashboard_helper.py       # 신설. 셸이 표현할 수 없는 명령의 실행체
└── dashboard_template.html   # 기존. 손대지 않는다
tests/
└── commands/
    ├── __init__.py
    └── test_dashboard_helper.py   # 순수 로직만 (stdlib unittest)
```

`commands/` 전체가 `install.sh` 의 `cp -R "$source/." "$target/"` 로 통째 배포되므로
(실측: `install.sh:438` `copy_directory_contents`) 새 파일은 자동으로 따라간다. 선례도 있다 —
`commands/dashboard_template.html` 이 이미 비-`.md` 파일로 이 디렉토리에 있다.

**헬퍼는 `python3 <경로>` 로 호출한다.** 실행 비트에 의존하지 않으므로 `cp -R` 의 모드 보존
동작이나 `chmod +x` 단계가 설계에 등장하지 않는다.

### 4.1 헬퍼 자기 탐색 — 닭과 달걀의 해소

옛 2단 탐색은 셸 `for` 루프였고(main L538) 그것이 거부 대상이다. 대체는 **2분기 `if`** 다 —
`$HOME` 은 관문이 허용하는 유일한 환경변수이고(M7·M8), 2분기 `if`/`else` 도 통과한다(M14).

> **정정(M16, 2026-09-23 EnterWorktree 격리 메인 세션 실측, v2.1.280)** — M14 는 서브에이전트가
> EnterWorktree 가 아닌 일반 워크트리 폴더에서 잰 것이라 격리 검사가 걸리지 않는 조건이었다.
> **EnterWorktree 로 격리된 세션에서는 아래 then 갈래(`python3 "$HOME/…"`)가 거부된다** — 관문은
> `$HOME` 확장이 아니라 python3 **프로그램 자리**(첫 피연산자)에 실행 시점 값이 오는 형태를
> 막는다. 근본 해결로 두 갈래의 `python3` 뒤에 `-- ` 를 넣었다.

```
if [ -f "$HOME/.claude/commands/dashboard_helper.py" ]; then python3 "$HOME/.claude/commands/dashboard_helper.py" <서브커맨드> [인자…]; else python3 .claude/commands/dashboard_helper.py <서브커맨드> [인자…]; fi
```

> 위 코드블록은 M14 시점(정정 전)의 이력이다 — 현행 런처는 두 갈래 모두 `python3 -- ` 형태다
> (`python3 -- "$HOME/…"`·`python3 -- .claude/…`, `rules/workflow/role-separation.md`·
> `commands/dashboard.md` 「헬퍼 스크립트」 절 참고).

- 이 한 줄이 **옛 `dz_path=…` 줄의 자리를 그대로 물려받는다** — 「대시보드 경로 규칙」 절이
  한 번 정의하고, 대시보드에 접근하는 모든 블록이 이 형태로 시작한다. 반복 게재도 옛 규칙과
  같은 관례다(옛 줄은 15회 반복됐다).
- 해결 순서는 **전역 → 프로젝트**로 템플릿과 같다(근거는 「템플릿 파일」 절의 커맨드 우선순위).
- 헬퍼가 두 경로 모두에 없으면 두 번째 분기가 `No such file` 로 실패한다. 문서는 이 출력을
  `NOTEMPLATE` 와 같은 등급의 **보고 후 중단** 사유로 규정하고 재설치를 안내한다.

### 4.2 모듈 경계 (헬퍼 내부)

프로젝트 CLAUDE.md 「외부 세계에 닿는 코드와 순수 로직을 분리한다」에 따라 한 파일 안에서
두 층으로 나눈다:

- **순수 층** — 입력→출력만 있는 함수. 단위 테스트 대상.
  - `resolve_dashboard_path(session_id: str | None) -> str` — 경로 규칙(SESSION/LEGACY) 판정
  - `render_dashboard(template_text: str, values: InitValues) -> str` — 앵커 6종 치환. 앵커
    등장 횟수가 1이 아니면 `AnchorMismatch` 예외
  - `escape_for_dom(raw: str) -> str` — `&`→`&amp;`, `<`→`&lt;`, `>`→`&gt;` 순서 고정
  - `pick_port(probe_results) -> tuple[int, str] | None` — REUSE 우선 판정
- **I/O 층** — 파일·소켓·프로세스에 닿는 얇은 껍데기. 순수 층을 호출하고 폐쇄 어휘를 출력한다.

예상 규모 ~250줄(추정). **400줄을 넘으면** 순수 층을 `commands/dashboard_render.py` 로
분리한다 — 지금 미리 나누지 않는다(YAGNI).

### 5.2 폐쇄 어휘 — 유지·신설·폐기

**유지(문자 단위로 동일)**: `SESSION` `ABSENT` `RECENT` `STALE` `MKDIR-FAILED` `NOTEMPLATE`
`OK` `ANCHOR-FAIL` `REUSE` `FREE` `NONE` `EXISTS` `FOCUSED` `NOTFOUND` `UNSUPPORTED`.
`init-check`·`init-copy` 의 "N줄" 판정 규칙과 `ANCHOR-FAIL <횟수> <앵커>` 의 인자 순서도 그대로다.

**신설 2개** — 새 실패 경로가 실제로 생겨서만 추가한다(「일어날 수 없는 상황에 대한 에러 처리 금지」):

| 어휘 | 언제 | 행동 |
|---|---|---|
| `VALUES-INVALID` | `init-render` 의 values JSON 이 파싱되지 않거나 필수 키가 없다 | **파일을 쓰지 않고** 보고 후 중단. `ANCHOR-FAIL` 과 같은 fail-closed 등급 |
| `PREPARE-FAIL` | `serve-prepare` 의 `mkdir`/`symlink` 가 실패했다 | 티어 2로 내려앉는다(자동 발행의 실패 비차단 원칙) |

**폐기 0개.** `NOTFOUND` 는 `focus-tab` 의 2-a→2-b 인계 신호로 계속 쓰인다(§7 D6 에서 2-b 병합을
기각했기 때문에 이 어휘가 살아남는다).

### 5.3 `init-render` 의 입력 — `InitValues`

`init` 4단계의 값들을 **JSON 파일**로 넘긴다. 모델이 `Write` 도구로 쓰고, 경로를 헬퍼에 넘긴다.

```
InitValues (JSON object)
  project_name      : string   # init-copy 출력 첫 줄
  title             : string   # 사용자 제목 인자 (원문 — 이스케이프 전)
  progress_text     : string   # "0/N · 0%"
  updated_text      : string   # "갱신: 2026-09-03 17:02"
  owner_token       : string   # init-copy 출력 마지막 줄, [0-9a-f]{8}
  steps_block_lines : string[] # <ol>/</ol> 또는 <table>/</table> 을 포함한 완성된 교체 블록.
                               # 선두 공백 포함. 줄 배열이므로 개행 이스케이프가 필요 없다
```

- 파일 경로는 **`.claude/dashboards/init-values.json`** 로 고정한다.
  - `.gitignore` 에 `.claude/dashboards/` 가 있어 커밋되지 않는다(실측).
  - 리텐션 청소는 `-name '*.html'` 만 지운다(실측, main L536) — 이 파일은 쓸려나가지 않는다.
  - `init-copy`(1단계)가 `mkdir -p .claude/dashboards` 를 **모드와 무관하게** 수행하므로
    4단계 시점에 디렉토리는 반드시 존재한다(실측: main 의 해당 문단).
- **헬퍼는 이 파일을 지우지 않는다.** 매 `init` 이 덮어쓴다. 남겨 두는 것이 "이번 `init` 이
  정확히 무엇을 채웠는가"의 감사 기록이 되어, 문서에서 명령 본문이 사라지는 손실을 일부 보상한다.

> **검수 2회차(MEDIUM-1) 반영으로 위 고정 경로 결정은 더 이상 유효하지 않다.** 같은 프로젝트의
> 두 세션이 거의 동시에 `init` 하면 A 의 `Write` 이후 A 의 `init-render` 이전에 B 가 이 고정
> 파일을 덮어써 A 의 대시보드에 B 의 값이 렌더될 수 있다는 지적을 받았다(실제 재현은 하지
> 않았고 코드 경로상의 경쟁 조건으로 지적됨). 대응: 새 서브커맨드를 만들지 않고, 1단계
> (`init-copy`)가 이미 출력하는 소유 토큰을 파일명에 재사용해 경로를
> **`.claude/dashboards/{토큰}.init-values.json`** 로 세션별로 가른다 — Bash 호출이 늘지 않고
> (토큰은 4단계 시점에 이미 대화 컨텍스트에 있다), `init-render` 의 인자 형태(`<values.json
> 경로>`)도 바뀌지 않는다(값만 달라진다). 이 경로 규칙은 `commands/dashboard.md` 의 `init`
> 4단계에 있다 — 이 PRP 문서에는 새 규칙을 복제하지 않는다. 리텐션은 `dashboard_helper.py`
> 의 `_cleanup_stale_session_dashboards` 가 `*.html` 과 함께 `*.init-values.json` 도 8일 후
> 지우도록 확장했다(세션마다 새 파일이 생기므로 청소 없이는 무기한 쌓인다) — 위
> "리텐션 청소는 `*.html` 만" 서술도 더 이상 유효하지 않다. G2(T34)·서브커맨드 표·폐쇄
> 어휘는 변경이 없다(둘 다 값이 아니라 존재만 검사하므로).
>
> **검수 3회차(LOW) 반영** — `commands/dashboard.md` 의 위 4-a 설명이 이 세션 스코프화를
> `data-owner-token` 과 "동일한 안전성 가정"인 것처럼 서술했다는 지적을 받았다. 부정확하다
> — 두 충돌의 결과가 다르다. `data-owner-token` 충돌은 거짓 `MINE`/`FOREIGN` 판정(소유권
> 오판)을 낳지만, 이 값 파일의 충돌은 **다른 세션의 제목·진행률이 내 대시보드에
> 렌더링되는 크로스오버**를 낳는다. 정확한 특성: 충돌 확률은 무시 가능한 수준이고(토큰
> 8자리 hex, 동시 세션 2~3개 기준), 충돌해도 영향은 위 크로스오버로 국한된다. 대시보드
> HTML 경로는 전체 세션 UUID(128비트)를 쓰므로 이 충돌과 무관하다 — 값 파일만 앞
> 8자리(32비트)를 쓰므로, 값 파일만 충돌하고 대시보드 파일은 충돌하지 않는 비대칭
> 시나리오가 이론적으로 남는다(확률은 마찬가지로 무시 가능).
- `title` 은 **원문 그대로** 넣는다. `escape_for_dom` 은 헬퍼가 적용한다(현행과 동일 규칙·순서).
  이스케이프 주체를 모델에서 헬퍼로 옮기는 것이 규칙 중복을 없앤다.

### 5.4 `grep` 심의 계약

- 헬퍼는 받은 인자를 **해석하지 않고** 그 뒤에 해결된 대시보드 경로를 **마지막 인자로 붙여**
  `grep` 을 실행하고, stdout·stderr·종료 코드를 그대로 통과시킨다.
- 따라서 `-n`·`-c`·`-e` 조합과 출력 형식(`<줄번호>:<줄 전문>`)이 현행과 **바이트 단위로 같다.**
  이 성질이 필수인 이유: 모델은 이 줄 전문을 그대로 `Edit` 의 `old_string` 앵커로 쓴다.
- **DOM 셀렉터 패턴은 문서에 남는다.** 헬퍼는 `dz-step-`·`dz-log` 같은 셀렉터를 알지 못한다 —
  DOM 계약의 단일 출처가 `dashboard.md` 로 유지된다(새 드리프트 면을 만들지 않는다).

### 5.5 서버 기동 — 헬퍼와 인라인의 분업

`serve-prepare` 는 임시 디렉토리를 만들고 그 안에 대시보드 심볼릭 링크를 만든 뒤 **디렉토리
절대 경로만 출력한다.** 실제 기동 줄은 **문서에 인라인으로 남는다**:

```
trap 'exit 0' TERM; python3 -m http.server {포트} --bind 127.0.0.1 --directory {serve-prepare 출력}
```

이 분업의 이유는 §7 D5 에 있다. 결과로 `pkill -f "http.server {포트} --bind 127.0.0.1"` 의
매칭 대상과 `trap 'exit 0' TERM` 의 근거가 **한 글자도 바뀌지 않는다.**

## 6. 해법의 형태 — 후보 비교

### 후보 (A) 각 블록을 허용된 부분집합으로 다시 쓴다

- **경로 규칙에 적용 불가.** 셸에서 `$HOME` 이외의 환경변수를 읽을 방법이 없다(M1·M3).
- 나머지 블록에는 부분적으로 가능하나, 경로를 얻을 수 없으므로 **대시보드 파일에 닿는 블록은
  하나도 고칠 수 없다**(25줄 중 15줄이 경로 규칙 줄이다).

### 후보 (C) 모든 블록을 인라인 `python3 -c "…"` 로 다시 쓴다 — 인수 브리핑에 없던 후보

M15 가 이 후보를 열었다. **여러 줄 `python3 -c "…"` 는 관문을 통과하고 `CLAUDE_CODE_SESSION_ID`
를 직접 읽을 수 있다.** 즉 브리핑의 「이 규칙은 인라인 Bash 로는 원리적으로 표현 불가능하다」는
*셸* 에 대해서는 참이지만 *인라인 파이썬* 까지 포함하면 거짓이다. 명령 본문이 문서에 남는다는
큰 장점도 있다. 그런데도 **기각한다**:

1. **바이트 예산 래칫에 걸린다.** `main:tests/run.sh` 의 T22-163 은
   `DASHBOARD_MD_BUDGET_BYTES=95942` 를 `-gt` 로 검사하고, 실측치가 정확히 95,942B 다
   (`wc -c`). 주석에 적힌 설계 상한은 96,000B 로 **여유가 58바이트**다. `grep` 7곳만
   봐도 예산을 넘는다 — 지금 한 블록은 경로 줄 ~180B + grep 줄 ~60B 인데, 같은 일을 하는
   파이썬은 최소 그 두 배가 된다. 블록당 +200B 로 잡아도 7블록 = +1,400B ≫ 58B 다
   (**추정** — 파이썬 본문을 실제로 써서 재보지는 않았고, 블록의 현재 크기만 실측했다).
   반대로 (B)는 블록 본문 9종을 문서에서 덜어내므로 예산을 **줄인다**(줄어드는 양은 미측정).
2. **경로 규칙의 출처가 여러 개로 갈린다.** 문서는 「규칙을 파이썬에 다시 쓰지 않는다」를
   명시적으로 규정한다. (C)는 그 규칙을 9개 블록에 복제한다.
3. **`init` 4단계의 주입 차단 성질을 잃는다.** `python3 -c "…"` 는 **겹따옴표**이므로 셸이
   `$`·백틱·`\` 를 확장한다. 사용자 제목을 그 안에 넣으면 오늘 `<<'PY'` 가 막고 있던 주입
   경로가 열린다. 홑따옴표로 바꾸면 파이썬 본문의 홑따옴표를 전부 이스케이프해야 한다.

### 후보 (B) 스크립트 파일로 추출한다 — **채택**

M12~M14 로 우회가 완전함을 확인했다. (A)로는 아무것도 못 고치고, (C)는 위 세 가지에 걸린다.
(B)는 예산을 줄이고, 경로 규칙을 한 곳에 두고, 사용자 텍스트를 셸에서 완전히 떼어낸다.

## 7. 설계 결정과 근거

### D1 — 헬퍼는 **파이썬 1파일**이다 (`.sh` + `.py` 2파일 기각)

- 모든 서브커맨드가 경로 규칙을 필요로 하고, 그 규칙은 환경변수를 읽을 수 있는 곳에만 둘 수 있다.
  `.sh` + `.py` 로 나누면 규칙을 **두 언어에 복제**하거나 둘 사이에 값을 넘기는 층이 하나 더 생긴다.
- `init-render`(앵커 치환)와 `port-scan`(소켓·HTTP)은 어차피 파이썬이 필요하다.
- 한 언어면 인용 규칙이 하나다. 헬퍼 내부에 셸 인용이 등장하지 않는다.
- `python3 <경로>` 호출이므로 실행 비트·모드 보존이 설계에서 사라진다.
- 순수 층은 `python3 -m unittest` 로 직접 import 해 테스트할 수 있다(§8.1).

### D2 — 서브커맨드는 9개, 그중 `grep` 은 **얇은 심**이다

`locate`/`count` 처럼 절차별 서브커맨드를 만들면 DOM 셀렉터가 헬퍼로 복제되어 새 드리프트
면이 생긴다. `grep` 심은 경로만 공급하고 나머지를 그대로 넘기므로 (i) 패턴이 문서에 남아
가독성이 유지되고 (ii) 출력 형식 드리프트가 원리적으로 불가능하며 (iii) 7개 블록을 한
서브커맨드로 덮는다.

### D3 — `init` 4단계의 셸 주입 차단은 **더 강해진다**

| | 오늘 (`<<'PY'`) | 제안 (`init-render <values.json>`) |
|---|---|---|
| 셸이 사용자 텍스트를 보는가 | 아니오(인용 heredoc) | **아니오** — 명령줄에 제목이 아예 없다 |
| 이스케이프 규칙 수 | 2 (셸 무확장 + 파이썬 `\\`·`\"`) | **1** (JSON 문자열 규칙) |
| 파싱 실패 시 | (해당 없음) | `VALUES-INVALID`, **파일 미기록** |

`Write` 도구는 Bash 관문을 거치지 않고 바이트를 그대로 쓴다. 홑따옴표 argv(M13)도 안전하지만
JSON 파일 쪽을 택한 이유는 `steps_block_lines` 가 **여러 줄 배열**이라 argv 로는 개행·인용
규칙이 다시 두 겹이 되기 때문이다.

`focus-tab` 도 같은 원칙으로 **URL 문자열을 인자로 받지 않는다.** `dashboard <포트>`·`hub <포트>`·
`file` 세 형태만 받고 URL 은 헬퍼가 조립한다 — 프로젝트 경로에 `'` 가 들어 있어도 인용이
깨지지 않는다. URL 템플릿 2종(`http://localhost:{포트}/dashboard.html`,
`http://localhost:{포트}/hub.html`)이 문서와 헬퍼에 각각 존재하게 되는데, 이 중복은 §8.3 의
G2 가드가 덮는다.

### D4 — 문서에서 명령 본문이 사라지는 손실을 3가지로 보상한다

이 스킬은 "절차를 읽으면 무엇이 실행되는지 정확히 안다"는 성질에 크게 의존한다. 보상 수단:

1. **「헬퍼 스크립트」 절 신설** — §5.1 의 표(서브커맨드 → 인자 → 출력 어휘 → 닿는 파일)를
   문서에 싣는다. 「템플릿 파일」 절이 템플릿에 대해 하는 일과 같은 역할이다.
2. **근거 주석의 이관** — 오늘 문서에 있는 "왜"들(`-mmin -30` 이 허브 기본값과 같아야 하는 이유,
   `|| true` 를 지우면 안 되는 이유, `is running` 검사를 지우면 빈 브라우저가 뜨는 이유,
   `--bind 127.0.0.1` 생략 금지, `open -g` 금지, `html.escape` 순서, 앵커 계수 검증, 프로젝트
   이름을 토큰보다 앞에 두는 이유)을 **헬퍼의 해당 코드 바로 위 주석으로 옮긴다.** 근거를
   문서에서 지우고 끝내지 않는다.
3. **문서↔헬퍼 정합 가드**(§8.3 G2) — 표와 실제 디스패치가 어긋나면 스위트가 실패한다. 이
   저장소의 확립된 관례다(T22-125·T25-104 등이 같은 모양).

### D5 — 서버 기동은 **`serve-prepare` + 인라인 기동**으로 쪼갠다

헬퍼가 기동까지 하면 프로세스 트리가 `Bash → python3 <helper> → python3 -m http.server` 가
된다. 그러면 `pkill -f "http.server {포트} --bind 127.0.0.1"` 이 오늘 함께 죽이던 래퍼 셸이
사라지고, `trap 'exit 0' TERM` 이 겨냥한 오탐(백그라운드 태스크가 실패로 표시되는 문제,
문서에 "이 하네스의 실측은 144"로 기록됨)이 **다른 메커니즘을 요구하게 된다.**

이 부분은 `log commit` 의 자동 종료와 `serve stop` 이 걸린 가장 되돌리기 어려운 지점이므로,
기동 줄을 문서에 **오늘 그대로** 남기고 헬퍼는 문서 루트 경로만 만들어 준다. 결과: pkill 패턴·
trap 근거·종료 코드 동작이 무변경이다.

> 위 문단의 "래퍼 셸도 함께 죽는다"는 **추론**이다(`pkill -f` 가 전체 명령줄을 매칭하고 오늘의
> `bash -c` 명령줄에 그 부분문자열이 들어 있다는 사실로부터). 이 세션에서 실행해 확인하지
> 않았다. 다만 설계는 이 추론이 틀려도 안전한 쪽(무변경)을 택하고 있다.

비용: 티어 1 경로에서 Bash 호출이 1회 늘어난다(`init` 과 `serve` 각각). `init` 이 세션당 1회
불린다는 전제에서 수용한다.

### D6 — 자동 발행 4-2(플랫폼·원격 판정)는 **이번 범위에서 병합하지 않는다**

검토한 대안: `focus-tab` 을 `open-target` 으로 넓혀 2-a(탭 포커스)와 2-b(`open`/`xdg-open`,
`$SSH_CONNECTION`·`$DISPLAY` 판정)를 한 서브커맨드로 합친다. 장점은 (i) 비교용 URL 과 실제로
연 URL 이 구성상 항상 같아진다 (ii) §3.1 의 환경변수 산문 지시가 함께 해소된다.

**기각 이유**: 2-b 는 오늘 **코드 블록이 아니다**(산문 지시). 코드 블록으로 존재하지 않는
것을 이번 변경에 끌어들이면 폐쇄 어휘가 `OPENED`·`FAILED`·`SKIPPED-REMOTE` 로 늘고, 자동 발행
4·5 절의 표와 T22-94·T22-102~104 가 함께 흔들린다. 지금 고치라고 요청된 것은 거부되는 블록이다.
2-b 를 건너뛰는 대가는 "SSH 세션에서 열지 말아야 할 URL 을 여는" 화면상의 오동작뿐이고
데이터 손실이 없다. URL 발산 위험은 D3 의 `<kind> <포트>` 표를 문서·헬퍼 공용 출처로 삼고
G2 가드로 고정해 대신 막는다.

**남는 한계를 문서에 명시한다**: 워크트리 격리 세션에서 4-2 의 원격·디스플레이 판정은
수행되지 않을 수 있다. 후속 과제로 §9 에 적는다.

### D7 — 디자인 패턴을 도입하지 않는다

서브커맨드 디스패치는 `dict[str, Callable]` 한 개(또는 `if`/`elif` 사슬)로 끝난다. 플러그인
등록·추상 기반 클래스·설정 파일을 만들지 않는다. 서브커맨드는 9개로 고정이고 늘릴 계획이 없다.

1. **`$(...)` 를 검출 대상에 넣지 않았다.** M5·M6 에서 `echo "x=$(pwd)"`·

   - **거부 메시지가 한 번도 나오지 않아야 한다.**

   - 제목에 `$`·백틱·`"`·`'`·`<`·`&` 를 넣어 `init` 을 부르고, 결과 HTML 에 이스케이프된
     텍스트만 들어가고 셸이 아무것도 실행하지 않았음을 확인(D3 의 성질).
   - `log commit` 이 서버를 실제로 종료하고 백그라운드 태스크가 **실패로 표시되지 않음**을
     확인(D5 의 추론을 여기서 실측으로 바꾼다).
5. 허브(`/hub`)에서 이 세션의 대시보드가 파싱돼 보이는지 확인 — DOM 계약 무변경의 확인.
6. `python3 -m unittest discover -s tests -t <repo>` 가 기존 hub 테스트를 **모두 그대로**
   발견하는지 확인(경로를 넓힌 부작용 점검: 개수 비교).

### 8.5 권한 프롬프트

새 호출 형태(`python3 ~/.claude/commands/dashboard_helper.py …`)는 사용자의 Bash 허용 목록에
없을 수 있다. 자동 발행 5단계의 최초 1회 안내(`Bash(python3 -m http.server:*)` 등)에 한 줄을
더한다. **이 세션은 실제 프롬프트 발생 여부를 확인하지 않았다(추론).**

## 9. 명시적 비목표

1. **DOM 계약·불변식·발행 티어·보고 형식을 바꾸지 않는다.** 허브 파서(`hub_parse.py`)와
   `tests/hub/test_hub_dashboard_contract.py` 는 무변경 대상이다.
2. **`init` 의 인자 파싱·모드 판정·`커밋`/`푸시` 제외·매트릭스 열 확정을 헬퍼로 옮기지 않는다.**
   더 결정적이고 테스트 가능해지겠지만 이번 요구와 무관하고, 흔들리는 테스트 범위가 커진다.
   (검토했고 기각했다.)
3. **`pkill`·`open`/`xdg-open`·허브 생존 판정·`python3 --version` 을 건드리지 않는다**(§3.2).
4. **자동 발행 4-2 의 원격·디스플레이 판정을 고치지 않는다**(§3.1·D6). 후속 과제.
5. **Bash 관문 자체를 조사·우회하지 않는다.** 관문의 구현을 읽지 않았고, 이 설계는 관문을
   회피하는 것이 아니라 **관문이 검사하지 않는 정상 경로**(스크립트 파일)를 쓴다.
6. **`commands/hub.md` 를 고치지 않는다** — 거부 대상 구문 0건(실측).

   > **후속(M16 근본 해결 확장, 2026-09-23)** — M16 으로 관문이 거부하는 것이 `$HOME` 확장이
   > 아니라 python3 **프로그램 자리**(첫 피연산자)에 실행 시점 값이 오는 형태 자체임이
   > 드러났다. 그 기준으로 다시 보니 `python3 "$HOME/…"` 형태가 `commands/hub.md` 에 12줄,
   > `commands/harness-update.md` 에 3줄 있었다(둘 다 이 항목 작성 시점의 G1 3구문 판단 밖이라
   > 세지 않았다). 두 파일도 대시보드 런처와 같은 방식(`python3 -- `)으로 고치고,
   > `tests/run.sh` T33-1 검사 대상을 dashboard.md·role-separation.md 2개에서 이 두 파일을
   > 더한 4개로 넓혔다.
7. **`dashboard_template.html` 을 1바이트도 건드리지 않는다**(「템플릿 파일」 절의 불변식).
8. **서버 기동 줄(자동 발행 2-a·`serve` 3단계, `trap 'exit 0' TERM; python3 -m http.server …`)을
   헬퍼로 옮기지 않는다** — 검수 2회차(HIGH-4) 지적. 이 줄은 D5 결정대로 문서에 그대로
   남아 있는데, 워크트리 격리 세션의 Bash 관문은 `trap` 이 든 명령을 거부한다(메인 세션·
   검수자 각각 실측 — §2 의 M1~M15 시점에는 이 패턴을 시험하지 않아 §3의 영향 범위 표에
   없었다). 결과: 그 세션에서는 자동 발행이 항상 티어 2로 내려가고 `serve` 는 항상 보고 후
   중단한다. `commands/dashboard.md` 의 두 지점(자동 발행 2-a·`serve` 3단계)에 이 사실을
   명시했다. G1(T33)은 이 실패를 구조적으로 잡지 못한다 — `trap` 을 거부 패턴에 넣으면
   D5 가 보존하는 이 줄 자체가 즉시 위반으로 걸리기 때문이다(tests/run.sh T33 주석 참조).
   후속 과제: 이 줄을 관문을 통과하는 형태로 바꿀 방법이 생기면(예: 관문이 `trap` 을 더 이상
   거부하지 않게 바뀌거나, `pkill`/하네스의 백그라운드 태스크 실패 오탐 문제(D5 근거)가 다른
   방식으로 해소되면) 재검토한다.
